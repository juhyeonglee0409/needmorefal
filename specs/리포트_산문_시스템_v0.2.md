# 리포트 산문 시스템 v0.2

> **지위**: 진단 보고서·검토용 요약·커버노트 중심의 산문 규칙층. design_print.md(시각)의 자매 — 그쪽이 '보이는 방식', 이쪽이 '읽히는 방식'. MASTER 관점에서는 산출물 다중 렌더링(internal/client/public)의 렌더링 규칙에 해당하며 MASTER 본문을 수정하지 않는다. 제안서·영업 장르는 v0.2의 직접 적용 범위가 아니며, §5 레지스트리에서 사례 발생 후 별도 규칙을 추출한다.
> **검증 기반**: 김달수 케이스 1사이클(10p 원본 → MCN 검토용 v2 → 커버노트 v0.4 → PDF) + 맥킨지 한·영 문서 교차 분석. v0.2 (2026-06-17).
> **동결 원칙**: 본 문서는 사례에서 작동 확인된 규칙만 담는다. 장르 템플릿(목차 스켈레톤)은 동일 장르 사례 2건 누적 전까지 작성 금지 — §5 레지스트리로만 관리.
> **실행**: 본 문서는 규칙 원본(참조용)이다. LLM이 산출물을 생성·수정·검수할 때의 실행 순서·입력·출력·충돌 우선순위는 별도 실행 래퍼(`리포트_산문_실행래퍼_v0.1.md`)에서 정의한다.

## 1. 문체 3층 규칙

| 층 | 문체 | 적용 위치 |
|---|---|---|
| 분석이 말한다 | 다체 ("~이다, ~권장한다") | 본문 서술 전체. 화자를 지우고 분석이 스스로 서게 한다 |
| 데이터가 말한다 | 음슴체·명사형 ("~유지됨", "+227% 성장") | 표 안, 핵심 수치 불릿, 한계 목록 |
| 사람이 말한다 | 합니다체 | 커버노트(서간), 동의 고지, 디스클레이머, 연락처 — 약속과 안내의 층 |

근거: 합니다체는 '제안서·영업' 장르 신호, 다체는 '보고서·리서치' 신호. 같은 기능 단위 안에서 문체를 섞지 않는다. 본문 문단은 다체, 표·수치 불릿·한계 목록은 음슴체·명사형, 커버노트·고지·디스클레이머·연락처는 합니다체를 쓴다. 기능 단위가 바뀔 때만 문체 전환을 허용한다. (맥킨지 한국어 요약 관행과 동형 — 기관 소개·디스클레이머만 합니다체.)

## 2. 수신자 축과 해상도

문서는 세 독자를 동시에 섬긴다. 위에서 아래로 신뢰를 위임한다.

- **30초 독자** (의사결정자에게 전달하는 사람): 커버노트 1p — 한 줄 결론 / 핵심 발견 3 / 수신자 입장에서 본 의미 / 다음 단계. 영업 제안 금지.
- **10분 독자** (검토 담당): 본문. 섹션마다 **한 줄 요약(굵게)** 선행 — 요약만 이어 읽어도 논지가 성립해야 한다.
- **정밀 독자**: 원문(풀 리포트)에 위임. 본문 말미에 신뢰 위임 문장 — "본 문서는 전체 리포트(Np)를 재구성한 요약본이며 상세 방법론·검증은 원문 수록."

**해상도 규칙** (상위 독자로 갈수록 적용):
- 전문 통계 용어 제거, 도메인 실무 용어는 유지 (전문성 축 교체 — 독자의 전문성에 맞는 축으로).
- 비율은 직관 환산: "0.51%" → "1,000명당 5명". 정밀도 다운그레이드: "약", "~대", "이상".
- 도표는 제목이 곧 주장인 것만 생존. 표 4개 초과 시 산문 압축 먼저 검토.

**전문성 보존 규칙** — 상위 독자용으로 간결화하더라도 아래 정보는 삭제하지 않는다:
- 핵심 수치의 원 단위와 비교 기준
- 데이터 출처
- 방법론상 한계
- 강건성 여부
- 원문 또는 근거 섹션 위치

전문 통계 용어는 제거할 수 있으나, 판단에 필요한 조건은 쉬운 말로 재서술하거나 원문에 위임한다. 정밀도 다운그레이드는 독자의 직관을 돕기 위한 것이며, 의사결정 기준값·계약 조건·핵심 비교 수치에는 적용하지 않는다. 핵심 결론의 직접 근거, 강건성 확인, 비교 조건 표는 표 수 제한보다 우선한다.

## 3. 구조 패턴 (사례 확인됨)

- **결론 카드 ≤2** — 수신자가 윗선에 옮길 문장을 디자인이 지정한다(인용 블록 승격). 문서 첫 결론 + 마지막 선언.
- **섹션 = 리드(한 줄 요약) → 전개**. 리드는 결론 선행, 전개는 근거.
- **한계 섹션 의무** — 번호 목록·음슴체. 데이터 출처 한계, 순위 해석 폭, 미포함 비교, 추적 예정 항목.
- **권고의 우선순위화** — 수신자의 자원 배분 관점으로 정렬 ("효과가 큰 순서"). 각 권고에 근거 섹션 역참조.
- **용어 단일화** — 문서 내 동의어 금지 (리포트/보고서 혼용 같은 것). 최종 패스에서 grep 검증.

## 4. 정직성 조항 (방법론 연동)

- **단정 어휘 등급**: 확실(데이터 직접) / 거의 확실(강건성 검증 통과 — "어떤 조건에서도 유지됐다") / 관찰됨(패턴, 인과 미검증) / 추정·예정(검증 전). 등급을 건너뛰는 표현 금지.
- **검증 전 권고에는 단서 의무**: "초기 관찰 기반이며 실행 단계에서 수치로 검증 예정" — 권고를 빼는 게 아니라 등급을 정직하게 단다.
- **검증 주체 표현**: "독립 검증" 금지 — 실제 외부 독립 주체가 있을 때만 허용. "복수 AI 모델 교차검토"는 해석 일관성 점검이며, 원자료 검증·독립 감사·재계산 검증을 대체하지 않는다. 실제 수행한 경우에만 "비교 조건 N종 재계산", "원자료 재계산", "강건성 확인"을 쓴다.
- **외부 데이터 고지**: 플랫폼 공식 원자료가 아닌 경우 명시 + "절대 수치보다 추세·상대 위치 중심" 해석 지침 동반.
- **로컬 앵커의 비례 원칙**: 수신자 친화 사례를 승격하되 주장의 무게와 배치의 무게를 일치시킨다 (맥킨지 카카오뱅크 승격의 경계 교훈).
- **무명 분석가 보정**: 브랜드가 증거를 대신하지 못하므로 요약본에도 표·강건성 문장 등 증거 밀도를 맥킨지식 요약보다 두껍게 유지한다.

## 6. 변경 절차

- 사례 기반 개정만: 새 규칙은 실제 문서에서 작동이 확인된 뒤 등재한다. 문서가 증거를 앞서가지 않는다.
- 같은 장르 2건 누적 시: 교집합을 장르 템플릿으로 추출하고 §5 상태를 갱신. 단 2건 누적은 템플릿 후보 추출 조건이며, 고정 템플릿화에는 예외·차이·실패 사례 검토가 필요하다.
- 장르 3종 이상 검증 + 규칙 중복 발생 시: 커널/컨텍스트 분리 검토 (디자인 시스템과 동일 경로).
