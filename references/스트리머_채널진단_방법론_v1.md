## 0. 사전 정의

### 0.1 적용 대상

이 방법론은 다음 조건을 만족하는 스트리머 채널에 작동한다.

- **플랫폼:** 치지직 (트위치·아프리카·유튜브 라이브는 코호트 데이터 가용성 확인 후 적용 가능)
- **규모:** 팔로워 1천~3만 (그 이상은 코호트 상한, 그 이하는 데이터 매칭 어려움)
- **데이터:** 본인 채널의 일별 통계 1년치 접근 가능
- **카테고리:** 코호트 모집단을 만들 수 있는 카테고리. 모집단 200명 미만 카테고리는 적용 곤란.

### 0.2 필요한 데이터

| 데이터 | 최소 | 권장 | 이상 |
|---|---|---|---|
| 본인 일별 통계 | 6개월 | **1년** | 1년+ |
| 코호트 모집단 | 카테고리 상위 500명 | **2,000명** | 전체 |
| 팔로워 데이터 | 코호트 매칭용 | 6,000위 이상 | 전체 |
| 본인 진술 | 채널 소개·인터뷰 1건 | **+ 시청자 반응 샘플** | + 1:1 인터뷰 |
| 콘텐츠 샘플 | 최근 방송 1개 | 최근 3~5개 + 숏폼 | 시기별 샘플 |

**최소 미만이면 시작하지 말 것.** 6개월 데이터로 시작하면 추세를 오판한다(§2 함정 참조).

### 0.3 산출물 정의

한 케이스에서 만드는 산출물은 다음 7종이다.

| 산출물 | 대상 | 형식 | 단계 |
|---|---|---|---|
| project.json (레지스터) | 내부 | 의사결정 기록 | 전 단계 |
| 코호트 데이터 + 방법 문서 | 내부 | CSV + MD | §4 |
| 로드맵 (내부 전략 문서) | 내부 | MD | §6·§9 |
| 친근형 리포트 (선택) | 클라이언트 본인 | HTML | §9 |
| 정식 컨설팅 리포트 | 클라이언트 (또는 의뢰자) | MD → PDF | §9 |
| **실행 매뉴얼** | 클라이언트 | MD | **§10** |
| **트래킹 시트** | 클라이언트 + 우리 | CSV/시트 | **§11** |

### 0.4 한 케이스 비용 추정 (v1, 2 케이스 기준)

- **분석 단계 (§0~§9):** 약 7~10 작업 세션 (1세션 = 집중 2~3시간)
- **실행 단계 (§10~§12):** 약 5~8 작업 세션 (시간 분산 — 클라이언트 실행 주기에 종속)
- **단계별 가중치:** §1·§2·§3·§5가 분석 비용의 약 50%
- **Stage별 가중치:** 입력 수집·분석 작업이 비용의 70%, 산출·실행 지원이 30%

⚠️ **사업화 관점에서 가장 중요한 미지수.** 분석 비용을 절반으로 줄여야 단가가 맞는다. 실행 단계 비용은 *체크리스트·템플릿화*로 줄이기 가능.

### 0.5 사전 합의 표준 절차 *(v1 신설)*

**적용 대상:** 정식 의뢰 케이스. 친분 관계라도 *케이스 사용·익명화 사례 활용* 동의는 받음.

#### 0.5.1 합의 필요 영역 (4단계 분류)

| 단계 | 영역 | 처리 |
|---|---|---|
| 1단계 | 분석에 명확히 필요 | 공유 권장 |
| 2단계 | 사업 지속성 (재정) | **본인 선택** — 위치만, 액수 아님 |
| 3단계 | 자발 노출 시에만 | 직접 캐지 않음 |
| 4단계 | 받지 않음 | 자발 언급해도 기록·외부 공유 안 함 |

#### 0.5.2 합의 방식 두 형식

| 형식 | 적용 |
|---|---|
| (가) 공식 합의서 | 정중체·표준형 — 정식 의뢰 |
| (나) 평서체 합의 | 인터뷰 자연 흐름 — 친분 관계·무료 컨설팅 |

→ 두 형식 모두 *영역 분류 합의*가 핵심. 형식 자체는 상황에 맞춤.

#### ⚠️ 함정

- **합의 영역을 *분석가 시점*에서만 정함.** 공유 영역은 *최소 필수 + 본인 선택*으로 설계.
- **자발 노출을 *동의*로 착각.** 본인이 인터뷰 중 자발 발화한 정보가 *전부 공유 동의*는 아님. 민감 영역(재정·신원·관계 등)은 *별도 확인*.

#### 산출물

- 합의서 발송본 또는 합의 회신 기록
- project.json에 합의 영역 명시

### 0.7 케이스 진행 단계 *(v1 신설)*

§§ 분석 단계와 *별도로*, 케이스 운영 측면의 진행 단계를 명시. 이 둘은 *겹치며 진행*된다.

#### 0.7.1 케이스 진행 6단계 (Stage)

```
[Stage A] 접촉·동의
[Stage B] 입력 수집       — §0~§4 자료 단계와 겹침
[Stage C] 분석 작업       — §1~§8
[Stage D] 산출물 작성     — §9
[Stage E] 전달·반응
[Stage F] 실행 지원       — §10~§12
```

#### 0.7.2 클라이언트 응대 단계 (접점)

```
[접점 1] 의뢰·동의
[접점 2] 입력 수집 (자기소개·인터뷰)
[접점 3] 중간 미팅 (1차 발견 공유·정렬)
[접점 4] 후속 입력
[접점 5] 산출물 전달
[접점 6] 실행 지원·트래킹
[접점 7] 사후 응대 (장기 관계)
```

#### 0.7.3 Stage·접점 매핑

| Stage | 일반 접점 | 비고 |
|---|---|---|
| A | 접점 1 | |
| B | 접점 2 | 분석 자료 수집 |
| C | 접점 3 | 중간 발견 공유 — *생략 시 산출물 어긋남 위험* |
| D | (내부 작업) | |
| E | 접점 5 | |
| F | 접점 6·7 | 실행 단계 진입 |

#### ⚠️ 함정

- **§§ 분석 단계만 보고 *클라이언트 응대 단계 빠뜨림*.** 클라이언트는 *기다리는 입장*에서 *진행 상황 모름*. **클라이언트 응대 단계 별도 트래킹.**
- **Stage C·D 분석 작업에 매몰되어 *Stage E·F 전달·실행 잊음*.** v0에서 케이스 클로즈가 *분석 완료 = 케이스 끝*인 것처럼 박혔으나, 실제로는 *분석은 절반*. 실행이 본질. **§13 클로즈 기준이 *실행 단계 완료*까지 포함**.

#### 산출물

- project.json status에 *Stage 현재 위치 명시*
- 접점 진행 기록 (case_log)

## 1. 정체성 추출

### 1.1 입력 자료

다음 세 가지를 균형 있게 수집한다.

| 층 | 출처 | 질문 |
|---|---|---|
| **본인 인식** | 채널 소개, 인터뷰, 본인 발화 | "본인이 자신을 뭐라고 정의하는가" |
| **콘텐츠 실제** | 최근 방송·숏폼 샘플 | "실제로 무엇을 하고 있는가" |
| **시청자 수용** | 채팅·댓글·반응 패턴 | "시청자가 무엇 때문에 보는가" |

### 1.2 추출 원칙 — 3층 일치점

세 층이 *겹치는 지점*이 진짜 정체성이다.

- 본인은 말하는데 콘텐츠엔 안 보임 → **희망사항** (정체성 아님)
- 콘텐츠엔 있는데 본인 인식 없음 → **잠재력** (확정 전)
- 시청자만 보는데 본인·콘텐츠에 없음 → **오해** (정체성 아님)
- **셋 다 있음 → 정체성 확정**

### 1.3 한 줄 포지셔닝 도출

3층 일치점을 한 문장으로 압축. 형식은 케이스에 따라 다름 — *반전 매력 + 관계 비유* 또는 *의도-수용 정합* 등. 형식 고집보다 *해당 케이스의 본질을 담는 형식*이 우선.

→ 케이스별 예시는 부록 E 케이스 간 비교 참조.

### 1.4 콘텐츠 진입/잔류 분리

정체성 위에서 콘텐츠의 두 기능을 명시.

- **진입(유입) 동력:** 시청자가 *처음 클릭*하는 이유 — 표면적·기능적
- **잔류(체류) 동력:** 시청자가 *남는* 이유 — 정서적·관계적

이 둘을 혼동하면 콘텐츠 전략이 흔들린다.

### 1.5 어휘 처리 원칙 *(v1 신설)*

본인 자발 어휘를 어떻게 보존·정제할지의 원칙. 어휘는 *정체성 표지*인 동시에 *분석 객관성*과 충돌할 수 있다.

#### 1.5.1 문서별 처리 원칙

| 문서 | 본인 어휘 처리 | 분석 진술 처리 |
|---|---|---|
| 인터뷰 원본 | 전부 보존 (변경 금지) | — |
| §1 입력자료 요약 | *본인 자발 어휘만* 따옴표로 보존 | 표준어 |
| project.json claim 본문 | 핵심 어휘 1~2개만 보존 | 나머지 표준어 |
| 한 줄 포지셔닝 | 핵심 어휘 그대로 (정체성 표지) | 연결 문장 표준어 |
| 정식 클라이언트 리포트 | 최소 인용 (따옴표 + "본인 표현" 명시) | 본문 표준어 |
| 친근형 클라이언트 리포트 | 어휘 톤 일부 차용 가능 | — |
| 익명화 사례 | 기능어로 치환 | 전부 표준어 |

#### 1.5.2 본인 자발 어휘 식별

본인 자발 어휘 = *본인이 직접 명명한* 어휘. 분석가 합성·번역이 아님. 자발 어휘는 *컨설팅 산출물·외부 채널 운영*에서 *그대로 활용 가능*.

#### 1.5.3 처리 우선순위

- 본인 어휘가 *결을 정확히 담음* → 보존
- 본인 어휘가 *분석 객관성 흐림* → 표준어 정제 (분석 진술에서)
- 충돌 시 → *문서 용도*에 따라 결정

### ⚠️ 함정

- **방송 제목·표면 표현을 정체성으로 착각.** 데이터 확인 없이 단정 금지 (부록 B 참조).
- **본인 진술만 받기.** 본인은 *되고 싶은 자기*를 말하는 경향. 시청자 반응과 콘텐츠 실제를 반드시 교차.
- **에디터 통합 해석을 *본인 명시 확인 없이* 확정 (v1 신규).** 추출 가설은 *본인 검증*을 거쳐야 확정 (부록 D 참조).
- **§1 단계에서 §6·§7·§9 발화 자연 발생을 *§1로만 묶어두기* (v1 신규).** 정식 의뢰·외부 피드백 부재 클라이언트에서 자주 발생. *§1 입력자료와 별도로 §6·§7·§9 진입 자료를 따로 정리*하여 후속 분석에 연결.

### 산출물

- 한 줄 포지셔닝 문장 1개
- 진입/잔류 동력 정의
- 3층 입력 자료 요약 노트
- (필요 시) §6·§7·§9 진입 자료 별도 문서

## 2. 데이터 수집 및 정합성 확인

### 2.1 채널 자체 데이터

**일별 통계 1년치를 받는다.** 6개월·반년은 시작하지 말 것 (§ 함정).

받아야 할 컬럼:
- 날짜, 팔로워(누적), 방송시간
- 최고 시청자, 평균 시청자
- 채팅 (6분 평균 또는 누적)
- 뷰어십(시청량) — 있으면

### 2.2 코호트 모집단 데이터

대상 채널의 카테고리에서 **상위 2,000명 랭킹**을 확보한다.

- 출처: 외부 통계 서비스 (소프트콘 등)
- 최소 컬럼: 채널명, 방송시간, 최고시청자, 평균시청자, 뷰어십
- 카테고리: 대상 채널의 *주 카테고리* 기준 (최근방송 1개로 판정하면 노이즈 큼 — 카테고리 분포 확인 후 결정)

### 2.3 팔로워 매칭 데이터

코호트 채널들의 *팔로워 수*는 모집단 랭킹에 안 들어있을 수 있다. **별도 팔로워 랭킹**(상위 6,000위) 데이터를 매칭한다.

### 2.4 데이터 검증 절차

받자마자 다음 5가지 확인. **하나라도 안 맞으면 다음 단계 진행 금지.**

1. **기간 완전성** — 누락일 없는가, 끝일이 최신인가
2. **이상치** — 최고시청자가 평균시청자보다 작은 경우 등
3. **방송시간 분포** — 0.1h 미만·24h 이상 빈도 확인
4. **카테고리 일관성** — 대상이 모집단 카테고리와 정말 맞는가
5. **본인 데이터 ↔ 모집단 데이터** — 같은 채널의 수치가 양쪽에서 일치하는가

### ⚠️ 함정

- **6개월 데이터로 추세 판단.** 6개월은 *계절성·시즌 효과 통제 불가.* 무조건 1년 (부록 B 참조).
- **카테고리 판정 1건 의존.** 최근방송 1개로 카테고리 판정하면 노이즈. 분포로 보고 *주로 어디서 방송하는지* 확인.
- **모집단 누락.** "카테고리 2,000명"이 *전체 스트리머*가 아니라 *상위 2,000명*임을 명심.

### 산출물

- 본인 일별 데이터 CSV (1년)
- 코호트 모집단 CSV (2,000명)
- 팔로워 매칭 데이터
- 검증 통과 체크리스트

## 3. 측정 보정 — 노방종/장시간 효과

### 3.1 평균 시청자 왜곡 원리

**평균 시청자 = 총 시청량 ÷ 방송 시간.** 방송시간이 길어지면 (시청자 적은 새벽·심야 시간 포함) 분모가 팽창하여 평균이 *기계적으로* 깎인다. *수요 감소 아님, 측정 효과.*

### 3.2 노방종 식별 기준

- **임계:** 하루 방송시간 14시간 이상
- **상습 판정:** 1년에 5일 이상 14h+ 또는 par(방송시간/평청) > 4

이 기준에 걸리는 *날*과 *채널*을 별도 표시한다.

### 3.3 보정 방식 (택1 또는 병용)

| 방식 | 계산 | 장점 | 단점 |
|---|---|---|---|
| **A. peak 비율법** | 보정평청 = 최고시청자 × 0.62 (정상채널 중앙비율) | 단순, 노방종 robust | 단발 spike에 취약 |
| **B. 시간가중 평균** | Σ(평청×시간) ÷ Σ시간 | 정밀, 분기 비교 강함 | 채널 단위 적용 시 분모 한쪽으로 작용 |
| **C. 노방종 제외 평균** | 14h+ 날 제외하고 단순 평균 | 직관적 | 데이터 손실 |

**권장:** 채널 단위 비교(코호트) → A. 시계열 분석 → B. 그래프용 → C.

### 3.4 권장 지표 체계

이후 모든 분석에서 다음 우선순위 적용.

| 순위 | 지표 | 용도 |
|---|---|---|
| 1 | 최고 시청자 (peak) | 노방종 robust 규모 지표 |
| 2 | 채팅 (6분 평균) | 코어 참여도 |
| 3 | 보정 평균 시청자 | 비율 산정 |
| 보조 | 원시 평균 시청자 | 단독 사용 금지 |

### 3.5 노방종 0일 케이스 처리 *(v1 신설)*

대상 채널이 1년 중 노방종 0일인 경우, §3 보정이 *거의 미적용*되는 케이스.

#### 처리 방식

- **§3 보정 자체는 *통과* 처리.** 보정 효과 없음. 다만 *원시 평균을 그대로 쓸 수 있다는 확인 자체*가 §3의 산출물.
- **권장 지표 체계는 그대로 적용.** peak 1순위, 채팅 2순위, 평청은 *원시 그대로* 사용 가능.
- **§5.5 보정 견고성도 *통과*.** 원시 = 보정이므로 자동 견고.

#### 함의

- 노방종 0일 케이스는 *§3 부담이 낮음*이라 케이스 비용 감소
- 그러나 *§3 함정*은 여전히 점검: 본인이 *향후 노방종 시도 의향* 있는지, 코호트에 *노방종 채널 비중*이 어떻게 되는지

### ⚠️ 함정

- **특정 시기 평청 급락을 진단으로 받기.** 평청 변동 → 먼저 *그 시기 방송시간 분포* 확인 (부록 B 참조).
- **노방종을 "전략"으로 무비판 수용.** 노방종이 *실제 효과 있는지*는 측정해야 한다.
- **보정값 한 가지로 단정.** *원시·보정 양쪽 제시*하고 보정 안 해도 결론이 유지되는지 확인.
- **노방종 0일 케이스에서 §3 자체를 건너뛰기 (v1 신규).** §3은 *생략*이 아니라 *통과 확인*. 산출물에 "노방종 0일 확인, 보정 미적용" 명시.

### 산출물

- 노방종 식별된 날 목록 (또는 "노방종 0일 확인" 명시)
- 코호트 내 노방종 채널 목록
- 보정값 적용된 채널별 지표 표 (또는 "보정 미적용" 명시)

## 4. 코호트 구축

### 4.1 동급 정의

**peak 기준이 기본.** 팔로워는 누적·휴면 포함이라 현재 라이브 규모와 어긋난다. peak가 실시간 규모의 직접 측정.

- **동급 범위:** 대상 채널 peak의 0.5배 ~ 2.0배

### 4.2 필터 단계

```
모집단 (카테고리 상위 2,000명)
  ↓ peak 0.5~2.0배 필터
1차 후보 (~200명)
  ↓ e스포츠팀·대회·기업 운영 계정 제외
2차 후보 (~190명)
  ↓ 팔로워 매칭 (별도 데이터)
3차 후보 (~150명)
  ↓ 명백한 이상치 제외 (휴면·신생 1~2개월 미만 등)
최종 코호트 (~130명)
```

### 4.3 포함 결정 — 경계 케이스

다음 케이스는 *표면으로 배제 금지.* 데이터로 확인 후 결정.

| 경계 케이스 | 점검 방법 | 판정 |
|---|---|---|
| 버추얼 채널 | 비-버추얼과 비율·충성도 분포 비교 | 분포 겹치면 포함, 명확히 다르면 분리 |
| 다른 게임 부주력 | 카테고리 분포 (방송 일수) | 주력 일치하면 포함 |
| 매우 작은 채널 | peak 하한 미만이면 별도 | 별도 |

### 4.4 강건성 검증 (필수)

코호트 결론을 확정하기 전에, **필터 조건을 바꿔도 대상 채널 위치가 유지되는지** 확인한다.

| 추가 필터 | 점검 의미 |
|---|---|
| 방송시간 10h+ / 20h+ / 30h+ 만 | 짧은 방송 채널의 비율 뻥튀기 우려 해소 |
| 카테고리 단일 (대상 채널 카테고리만) | 다른 게임 노이즈 제거 |
| 비-버추얼만 | 종족 차이 우려 해소 |
| 비-노방종만 | 노방종 보정 의존도 점검 |

**모든 필터에서 대상 채널이 상위권 유지하면 → 결론 강건.** 한 필터라도 위치가 크게 흔들리면 → 그 요인을 깊이 분석.

#### 4.5 이전 케이스 자산 재활용 *(v1 보강)*

새 케이스 진입 시, *이전 케이스의 코호트 데이터*가 적용 가능한지 먼저 점검. 적용 가능하면 데이터 수집 비용 감소.

- 점검 방법: 이전 케이스 코호트의 peak 범위·카테고리·플랫폼 결과 비교
- 적용 불가 시: 새 모집단 수집

### ⚠️ 함정

- **카테고리·버추얼을 직관으로 배제.** 분포 확인 후 결정 (부록 B 참조).
- **모집단 카테고리 오인.** 모집단이 "롤 카테고리"인지 "치지직 전체"인지 명확히. 외삽 함부로 금지.
- **peak 상한 편향.** peak 240 상한으로 자르면 *큰 채널의 비율*이 누락. 결론에 영향 없는지 점검.

### 산출물

- 코호트 명단 CSV (전 컬럼 + 보정값 + 플래그)
- 코호트 구성 방법론 MD (재현 가능하도록)
- 강건성 검증 표

## 5. 6단계 진단 분석

### 5.1 기술 통계

코호트의 *분포부터* 본다. 단일 채널 위치 보기 전에 모집단을 안다.

- 비율 분포 (히스토그램·분위수)
- 팔로워 분포
- peak 분포
- 방송시간 분포

### 5.2 대상 채널 다축 위치

3축 이상으로 본다.

| 축 | 의미 |
|---|---|
| 비율(진성도) 순위 | 효율 — 적은 팔로워로 많이 모으는가 |
| peak 순위 | 절대 규모 |
| 팔로워 작은순 순위 | 체급 |
| 방송시간 순위 | 활동 강도 |

### 5.3 동질성 확인

코호트가 정말 *동질 집단*인가? 대리지표로 결속력을 본다.

- **par (방송시간/평청):** 4 이상이면 노방종형, 분포 확인
- **충성도 (peak/평청):** 1.5~3 정상, 그 이상이면 단발 spike

### 5.4 핵심 관계 정량화

대상 채널이 도달하려는 목표(예: 1만 팔로워)와 현재 강점(예: 비율)의 관계를 *코호트 데이터로* 계산.

- 팔로워 vs 비율 상관 (log-log)
- 팔로워 구간별 중앙 비율
- 회귀 또는 분위수 추정

### 5.5 보정 견고성

§3에서 만든 보정값 의존도를 본다.

- 원시 지표로도 결론이 같은가? (다르면 보정 가정에 종속)
- 노방종 채널 빼면 코호트 어떻게 바뀌나?

### 5.6 시계열 추세

대상 채널의 1년 분기별 추세를 *노방종 제외* 정상일 기준으로.

- 분기별 최고시청자
- 분기별 채팅
- 분기별 팔로워 증가율
- 셋의 상대 속도 (어느 게 빠른가)

### 산출물

- 6단계 각 단계 결과표
- 진단 요약 1페이지 (성장 국면 / 정체 국면 / 어느 축 강점·약점)

## 6. 목표 트레이드오프 정량화

### 6.1 상충 식별

대상 채널의 *목표*(예: 1만 팔로워, 평청 100 등)와 *현재 강점 지표*(예: 비율) 사이에 충돌이 있는가? 코호트 데이터로 확인.

### 6.2 도달 가능 범위 추정

목표 도달 시 강점 지표가 어디까지 떨어지는지 추정.

**계산 방식 (택1):**
- A. 코호트 팔로워 구간별 중앙값 적용
- B. log-log 회귀 외삽

두 방식의 차이가 크면 *불확실 범위*로 양쪽 제시.

### 6.3 권장 목표 + 경보 하한선

- **권장 목표:** 코호트 동급에서 *현실적 상위권*에 해당하는 수치
- **경보 하한:** 그 이하로 떨어지면 "성장이 진성으로 전환 안 됨" 신호

### 6.4 영속 의향형 케이스 처리 *(v1 신설)*

본인이 *졸업 의지 없음 + 축소되더라도 계속* 영속 의향인 경우, *권장 목표*가 *도달점*이 아닌 *통과점*이 됨. 다음 두 질문 추가.

#### 두 결정 질문

1. **임계점 도달 vs 미달 지속 선택** — 목표를 *방송 수입 임계점 도달*로 잡을지 *임계점 미달 지속 가능 구조*로 잡을지. 단순 선택 아닌 *시간 축 분리* 가능 (단기 도달 / 장기 안정).
2. **데드라인 vs 영속 흡수** — 권장 목표(예: 1만)를 *데드라인형*(언제까지)으로 잡을지 *영속 흐름 안 통과점*으로 흡수시킬지.

→ 본인 답이 둘 중 하나로 정해지면 §6 권장 목표 형식 결정.

#### 영속 의향 식별 신호

본인 인터뷰에서 다음 발화 패턴 발현 시 영속 의향형 분류:

- "졸업 생각 안 함" 또는 동등 진술
- "축소되더라도 계속" 또는 동등 진술
- "본업 잡아도 계속" 또는 동등 진술
- 데드라인 질문에 *없다·따로 없다* 답

### ⚠️ 함정

- **목표 고정값 유지 가정.** "현재 비율을 1만에서도 유지"는 거의 불가능. *체급 상승 비용*을 인정한 목표가 현실적.
- **이분법 함정.** "비율 vs 규모, 택일"이 아니라 *어느 비율대를 지키느냐*가 진짜 질문.
- **본인 영속 의향 무시하고 표준 목표 적용 (v1 신규).** "1만 1년 안에 도달" 같은 표준 형식이 *영속 의향*과 어긋날 수 있음. 본인 인터뷰에서 *졸업·축소·영속 의향*을 확인하고 §6에 반영.

### 산출물

- 트레이드오프 정량 분석 1페이지
- 권장 목표 + 경보 하한 정의
- 영속 의향형 케이스: *목표 시간 구조* 명시 (도달점/통과점·데드라인/영속)

## 7. 콘텐츠 채널 효과 분석

### 7.1 외부 콘텐츠 유입 측정

대상 채널이 운영하는 외부 채널(유튜브 숏폼·인스타·트위터 등)이 *주 채널 성장에 기여*하는지 측정.

**핵심 질문:** 그 콘텐츠의 도달(조회수)이 주 채널 팔로워·시청자 증가로 *전환*되는가?

**방법:**
1. 외부 콘텐츠 게시일 식별
2. 게시일 전후 N일의 주 채널 팔로워 증가율 비교
3. 평소 증가율과의 차이 = 전환 효과

### 7.2 정체성 정합도 평가

전환되더라도, 유입된 시청자가 *정체성과 결이 맞는지* 확인. 결이 안 맞으면 잔류 안 함.

콘텐츠 유형별 분류:
- **결 맞음:** 주 카테고리와 일치하는 콘텐츠
- **결 일부:** 정체성을 변형하여 적용한 트렌드
- **결 안 맞음:** 순수 트렌드 추종 (도달은 크나 정체성과 무관)

### 7.3 권장 방향

- 결 맞음 콘텐츠 → **메인 레버**
- 결 일부 → 보조, 단 정체성 결합 필수
- 결 안 맞음 → 비주력 (도달용 환기 정도)

### ⚠️ 함정

- **조회수만 보고 효과 판정.** 도달 ≠ 전환. 조회수 5만이어도 주 채널 유입 없으면 효과 약.
- **외부 채널 자체 자산화 무시.** 주 채널 전환은 안 돼도 *외부 채널 자체*(예: 유튜브 구독)는 자산일 수 있음. 별도 분석.

### 산출물

- 콘텐츠 유형별 전환 효과표
- 권장 콘텐츠 방향

## 8. 외부 교차검증 (XGPS)

### 8.1 검증 대상 선정

*가장 뒤집힐 가능성이 있는 결론* 또는 *가장 중요한 결론*을 외부에 던진다.

권장 검증 대상 (3개 정도):
- 가장 큰 정정이 있었던 결론
- 핵심 보정 가정 (예: 노방종 보정)
- 핵심 전략 결론

### 8.2 발화 설계 — 우리 결론·보정 숨기기

XGPS 발화의 핵심 원칙: **외부 모델이 우리 결론을 추정하지 못하게.**

```
[금지] "이 채널이 성장 중이라는 우리 분석이 맞나?"
[금지] "이 데이터에 노방종 착시가 있는데 확인해줘"
[권장] "첨부한 데이터에서 이 채널이 성장 중인지 정체인지 판정해줘"
[권장] "첨부 데이터의 평균시청자 지표를 주 지표로 써도 되는지 평가해줘"
```

원시 데이터만 첨부, 우리 보정·해석은 *전부 제거.*

### 8.3 수렴·발산 처리

| 결과 | 해석 |
|---|---|
| **수렴** (외부도 같은 결론) | 신뢰도 상승, 단 *상식 수렴*이면 약한 검증 |
| **발산** (외부가 다른 결론) | **XGPS의 진짜 수확.** 우리 맹점 가능성. 데이터로 다시 확인. |
| **수렴이되 정밀화** | 외부가 더 날카로운 표현 제공 — 받기 |

**가장 흔한 실수:** 발산을 *우리 결론 지키는 쪽으로 재해석.* 무마하지 말고 *데이터로 가르거나 미해소로 열어둘 것.*

### 8.4 같은 종(LLM) 한계 명시

- 외부 모델도 LLM이면 *공유 편향* 존재 가능
- 통계 상식 수준의 수렴은 "독립 검증"이 아니라 *상식 재확인*
- 진짜 가치는 *발산*과 *정밀화*

### ⚠️ 함정

- **발산을 자기방어로 재해석.** 발산은 *우리에게 불리한 신호*일수록 무마 욕구가 커진다 — 의식할 것 (부록 B 참조).
- **수렴을 "검증 완료"로 단정.** 수렴은 신뢰도 상승이지 검증 완료 아님.

### 산출물

- XGPS 발화문 3종
- 수렴·발산·정밀화 결과 정리
- 미해소 발산은 *프로젝트 open 항목으로 박기*

- 통합 진단 등 *본인 명시 확인 필요한 결론*이 있으면 토론 배틀 보조 필수

### 9.3 토론 배틀 보조 — 형식 *(v1 신설)*

본인이 *납득 메커니즘으로 의사결정*하는 클라이언트용. 산출물 전달 직후 *예상 반론·자기 검열 발현*에 대응하는 도구.

#### 구조

```
[발견 X]
우리 분석: [요약]
근거: [데이터·발화·정황 3가지]

[예상 본인 반응]
"하지만 ~~~ 아닐까요?"

[우리 응답]
[근거 재확인 또는 본인 발화 인용]

[본인 추가 반론 시 점검]
[자기 검열 메커니즘 발현 여부 확인]
```

#### 작동 원리

- 본인이 *발견 전달 직후 자기 검열 발현*이 예상되는 결론에 미리 응답 준비
- 본인 의사결정 메커니즘 = *납득되면 받아들임*이라면, *납득 가능한 근거 + 토론 여지* 사전 설계
- 산출물 전달 후 *후속 인터뷰*에서 이 자료 활용

### 9.4 두 산출물의 차이

| 항목 | 내부 문서 | 클라이언트 리포트 |
|---|---|---|
| 레지스터 ID (C·K·O 등) | 명시 | **제거** |
| 자기정정 이력 | 명시 | **제거** (또는 부록에 짧게) |
| 통계 용어 (r=, p=) | 사용 | 친근형: 말로 풀기 / 정식형: 사용하되 해석 동반 |
| 미해소 항목 | open으로 명시 | 친근형: 액션으로 변환 / 정식형: 부록 후속과제 |
| 한계 명시 | 자세히 | 친근형: 생략 / 정식형: 부록에 정중하게 |

### 9.5 통합 진단 전달 형식 *(v1 신설)*

**상황:** §1·§5·§6·§7 분석 결과 *여러 발견이 하나의 뿌리에서 나옴*이 진단된 경우. 통합 진단을 *분산해서 전달*하면 본인이 *뿌리 못 봄*.

**원칙:** 통합 진단은 *별도 모듈*로 묶어 토론 배틀 보조에 배치. 본인이 *동일 뿌리로 인지하는지* 반응 관찰.

#### 위험 — 본인 명시 확인 안 됨

통합 진단은 *에디터 해석*. 본인 명시 확인 없이 단정 금지. 위험 자각 A.2 자기방어 편향과 동일 패턴 — §1 함정·부록 A.2 참조.

## 10. 실행 설계 *(v1 신설)*

> v0의 가장 큰 빈 곳. 분석 끝나면 *what만 있고 how 없음*. **이 영역이 컨설팅의 *진짜 가치 영역*.**

### 10.1 What → How 변환 원칙

분석 결과(§5·§6·§7·§8 산출)는 *전략 수준*. 클라이언트는 *행동 수준*이 필요.

| 수준 | 형식 예 |
|---|---|
| 전략 (§9 산출) | "X의 'Y'화" — 추상 |
| 액션 (§10) | "방송 시작 5분에 [행동] 3회·중간 [행동] 멘트 3회" — 동사+시간+횟수+대상 |
| 트래킹 가능 단위 (§11) | "방송 1회당 액션 횟수 / 1주일 누적 / 한 달 지표 변화" |

→ 같은 전략도 *액션·트래킹 단위*까지 내려야 클라이언트가 *실행 가능*.

### 10.2 액션 분해 4단계

1. **추상 → 구체 행동**
   - 전략 1개 → 행동 3~5개로 분해
   - 행동은 *동사 + 시간·횟수·대상* 형태

2. **시간 단위 매핑**
   - 각 행동을 *방송 한 회·일주일·한 달* 중 어느 단위에 적용할지 명시

3. **진입장벽 가장 낮은 1개 식별**
   - 클라이언트가 *내일 방송에서 시작할 수 있는* 1개를 명시
   - 진입장벽 ≠ 효과 크기. *지속 가능한 시작점*이 진입장벽 낮은 행동.

4. **본인 자원·기질 점검**
   - 클라이언트 시간 자원 (§I 답변 활용)
   - 클라이언트 기질 (예: 갈등 회피·완벽주의 회피·자가 회복 메커니즘)
   - 자원·기질에 맞지 않는 액션은 *외부 의존*으로 전환 (편집자 구인·소속사 위임 등)

### 10.3 실행 매뉴얼 구조

산출물 형식 (MD):

```
## 액션 1: [추상 전략 이름]

### 다음 방송에서 시작할 1가지
[가장 진입장벽 낮은 1개 행동 — 1문장]

### 매 방송 행동 (5~10분 추가)
- [구체 행동 1]
- [구체 행동 2]

### 매 주 행동 (1~2시간)
- ...

### 매 월 행동 (집중 작업)
- ...

### 트래킹 단위
- 방송 1회: [지표]
- 1주: [지표]
- 1달: [지표]

### 효과 판정 시점
- [N일 후 무엇을 보고 판단할지]

### 실패 시 조정 기준
- [지표 X 이하 → 행동 Y로 조정]

### 본인 자원·기질 고려
- 시간 부담: [추정]
- 자원 의존: [편집자·도구 등 / 자체 가능]
- 기질 호환: [본인 자기 검열·완벽주의 등 점검]
```

### 10.4 액션 우선순위

분석된 응대 우선순위(§9에서 박힘)에 따라 액션 우선순위 결정.

| 우선순위 | 액션 형태 |
|---|---|
| 1순위 (응대 핵심) | 자기 의심·자기 검열 등 *정체성 영역* 직접 해소 액션 — 데이터 발견 정량화·시청자 의견 수집 등 |
| 2순위 (콘텐츠) | 콘텐츠 확장·트렌드 대응 |
| 3순위 (외부 채널) | 유튜브·SNS 운영 — 본인 자원·진입장벽 점검 후 |
| 4순위 (구조 변화) | 소속사 가입·편집자 외주 등 — 본인 의사결정 시점에 따라 |

### ⚠️ 함정

- **추상 전략을 실행 매뉴얼로 위장.** 전략은 액션이 아님. 클라이언트가 *내일 무엇을* 하는지 안 보이면 실행 매뉴얼 아님.
- **진입장벽 무시한 액션 권고.** 본인 기질·자원에 안 맞는 액션은 *시도 안 됨* → 컨설팅 효과 0. 진입장벽 낮은 1개부터.
- **외부 의존 액션을 *본인 행동*으로 권고.** 본인이 *못 할 영역*은 외부 의존으로 명시 + *대안 액션 동시 제시*.

### 산출물

- 실행 매뉴얼 MD (액션별 1페이지, 우선순위 순)
- 진입장벽 가장 낮은 1개 행동 명시 (즉시 시작 가능)
- 효과 판정 시점·조정 기준 표

## 11. 실행 지원 *(v1 신설)*

> 클라이언트가 액션 실행 *중*에 우리가 무엇을 하는가. 분석가의 역할이 *진단*에서 *코칭*으로 이동.

### 11.1 트래킹 시트 설계

§10에서 정의한 *트래킹 단위*를 *실제 측정 가능한 시트*로 변환.

**구조:**

| 일자 | 방송회차 | 액션1 수행 (○/△/×) | 액션1 횟수 | 액션2 ... | 지표 X | 지표 Y | 본인 메모 |
|---|---|---|---|---|---|---|---|

- *액션 수행 자체* 트래킹 + *지표 변화* 트래킹
- 본인이 *직접 기록*하거나 *자동 수집* 가능한 형태로
- 부담 최소 — 한 방송당 입력 3~5분 이내

### 11.2 효과 판정 주기

| 주기 | 점검 내용 |
|---|---|
| 매 방송 | 액션 수행 자체 (○/△/×) |
| 매 주 | 액션 누적 + 단기 지표 (채팅·peak·체류) |
| 매 월 | 누적 지표 + 추세 (팔로워·구독·반복 시청) |
| 분기 | 응대 핵심 영역 (자기 의심·자기 검열) 변화 — 인터뷰 1회 |

### 11.3 조정 신호 처리

트래킹에서 발견되는 신호 3종 처리:

| 신호 | 처리 |
|---|---|
| **액션 수행 미이행** | 진입장벽 분석 — 시간? 기질? 자기 검열? 외부 의존 액션으로 전환 검토 |
| **수행했으나 지표 변화 없음** | 액션 자체 효과 부족 — 액션 조정 또는 응대 핵심 영역 재점검 |
| **지표 변화 있으나 부정적** | 액션 중단 + 원인 분석 + 대안 액션 설계 |

### 11.4 클라이언트 소통 주기

| 빈도 | 형식 |
|---|---|
| 매 방송 | 트래킹 시트 본인 기록 (우리 개입 없음) |
| 매 주 | 짧은 메시지 (트래킹 시트 점검·격려) |
| 매 월 | 1회 응대 (지표 리뷰 + 다음 달 조정) |
| 분기 | 깊이 인터뷰 (응대 핵심 영역 변화 점검) |

### 11.5 본인 자기 평가 기준 재조정

§3 측정 보정의 자기 평가 함의가 *실행 단계에서 다시 작동*. 본인이 *지표 의존 자기 평가*를 하는 경우, *액션 효과를 그 지표로만* 보면 *측정 착시*에 빠짐.

→ 트래킹 시트에 *행동 지표*(액션 수행 자체)와 *결과 지표*(채팅·peak)를 *분리* 명시.

### ⚠️ 함정

- **트래킹 시트가 *클라이언트 부담*.** 한 방송 3~5분 이상 걸리면 *지속 안 됨*. 부담 최소가 첫 원칙.
- **지표만 보고 본인 자기 평가 강화 (v1 신규).** 본인이 *자기 검열형*이면 단기 지표 미달이 *자기 의심 강화*로 작동. 트래킹 시트에 *맥락·정정 안내* 동반.
- **분기 깊이 인터뷰 빠뜨림.** 응대 핵심 영역(자기 의심·자기 검열) 변화는 *지표로 안 보임*. 분기 인터뷰 필수.

### 산출물

- 트래킹 시트 (CSV 또는 Google 시트 링크)
- 효과 판정 주기 정의표
- 조정 신호 처리 매뉴얼

## 12. 후속 응대 *(v1 신설)*

> 실행 단계 *이후* 장기 관계. 단기 컨설팅 끝나도 *케이스가 끝나지 않은* 영역.

### 12.1 응대 형태 3종

| 형태 | 시기 | 비용 |
|---|---|---|
| **선행지표 검증** | 산출물 전달 후 3~6개월 | 1~2 세션 |
| **재진단 (분기·반기)** | 분기·반기 | 부분 분석 재실행 |
| **장기 케이스 모니터링** | 1년+ | 가벼운 점검 |

### 12.2 선행지표 검증

§10 실행 매뉴얼에서 정의한 *효과 판정 시점*에 도달했을 때, 액션 효과를 *데이터로* 확인.

### 12.3 재진단 트리거

다음 신호 발견 시 *부분 재진단* 실행:

- 응대 핵심 영역(자기 의심 등)에 *큰 변화*
- 외부 환경 변화 (플랫폼·시장)
- 본인 사업 단계 변화 (전업화·축소·전환)
- 단기 지표의 *예상 외 변화* (급성장 또는 급락)

### 12.4 장기 케이스 모니터링

가벼운 형태:
- 분기 1회 짧은 점검 (15~30분)
- 본인 자발 질문 시 응답 (개방형)
- 새 발견·새 영역 발생 시 *재 패키징*

### 12.5 케이스 종료 결정

후속 응대도 영원하지 않음. 종료 결정 기준:

- 본인이 *컨설팅 졸업* 명시
- 본인 영속 의향과 *우리 응대 범위* 어긋남
- *데이터 부재로* 후속 분석 불가
- 본인이 *다른 체계*로 이동 (소속사 등)

→ 종료 시 *익명화 사례 활용 동의* 재확인.

### ⚠️ 함정

- **선행지표 검증 잊음.** 산출물 전달 시 *검증 시점 명시*하고 *프로젝트 open 항목으로 박기*.
- **재진단 트리거 인지 부재.** 본인 변화를 *외부 발견 없이* 알기 어려움. 트래킹 시트의 *분기 인터뷰* 또는 본인 자발 보고에 의존.

### 산출물

- 선행지표 검증 보고
- 재진단 결과 (트리거 발생 시)
- 케이스 종료 보고서 (종료 시)

## 13. 케이스 클로즈 기준 *(v0 §10 이동·갱신)*

### 13.1 분석 클로즈

다음 모두 충족 시 *분석 단계 완료* 선언.

- [ ] 정체성 확정 (§1 산출물)
- [ ] 코호트 구축 + 강건성 검증 (§4 산출물)
- [ ] 6단계 진단 완료 (§5 산출물)
- [ ] 트레이드오프 정량화 (§6 산출물)
- [ ] 콘텐츠 채널 효과 분석 (§7 산출물)
- [ ] XGPS 핵심 결론 검증 (§8 산출물)
- [ ] 클라이언트 리포트 1종 산출 (§9)
- [ ] 미해소 항목 open으로 박음

**용어 정정 (v1):** v0의 "하프 클로즈"를 **"분석 클로즈"**로 명명. *분석 완료*가 *케이스의 절반*이 아니라 *분석 단계의 종결*임을 명확히. 컨설팅 본질은 *§10 이후 실행 단계*.

### 13.2 실행 클로즈 *(v1 신설)*

분석 클로즈 + 다음 충족 시.

- [ ] 실행 매뉴얼 산출 (§10 산출물)
- [ ] 트래킹 시트 운영 시작 (§11 산출물)
- [ ] 진입장벽 가장 낮은 1개 행동 시작 확인 (본인 자발 또는 데이터)
- [ ] 단기 효과 1회 점검 (방송 1~3회 후)

### 13.3 완전 클로즈

분석 클로즈 + 실행 클로즈 + 다음.

- [ ] 선행지표 검증 1회 (산출물 전달 후 3~6개월)
- [ ] 본인 자기 평가 변화 (분기 인터뷰)
- [ ] 미해소 발산이 해결 또는 *영구 미해소 결정*

**일반적으로 완전 클로즈는 한 세션에 안 됨.** 분석 클로즈가 *분석 프로젝트*의 기본 종결, 실행 클로즈가 *실행 프로젝트*의 기본 종결, 완전 클로즈는 *장기 관계*의 종결.

### A.1 에디터 독주
