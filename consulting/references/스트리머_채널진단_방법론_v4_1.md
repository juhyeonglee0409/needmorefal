**v4 작성 원칙**

- v3의 §1~§15 흐름은 유지한다. 레지스터와 open ID의 연결을 깨지 않는다.
- 실전에서 검증된 것만 역주입한다. 1케이스 전용 발견은 함정/교훈으로 기록하되 일반 규칙으로 승격하지 않는다.
- Bridge는 새 판단자가 아니라 변환기다. CaseResult에 없는 결론을 만들지 않는다.
- 공개경계는 마지막 검열이 아니라 작성 시점의 필드다.
- 모든 산출물은 `client / internal / portfolio / public` 계열 중 하나에 속한다.

## 0. 사전 정의

### 0.1 적용 대상

이 방법론은 다음 조건을 만족하는 스트리머 채널에 작동한다.

- **플랫폼:** 치지직 (트위치·아프리카·유튜브 라이브는 코호트 데이터 가용성 확인 후 적용 가능)
- **규모:** 팔로워 1천~3만 (그 이상은 코호트 상한, 그 이하는 데이터 매칭 어려움)
- **데이터:** 본인 채널의 일별 통계 1년치 접근 가능
- **카테고리:** 코호트 모집단을 만들 수 있는 카테고리. 모집단 200명 미만 카테고리는 적용 곤란.

### 0.2 필요한 데이터

v1은 채널 성과와 코호트 비교에 필요한 데이터를 중심으로 정의했다. v2부터는 여기에 **수집 근거, 카테고리 판정 근거, 콘텐츠 세그먼트, 실행 장벽, 부재 인벤토리**를 추가한다.

| 데이터 | 최소 | 권장 | 이상 |
|---|---|---|---|
| 본인 일별 통계 | 6개월 | **1년** | 1년+ |
| 코호트 모집단 | 카테고리 상위 500명 | **2,000명** | 전체 |
| 팔로워 데이터 | 코호트 매칭용 | 6,000위 이상 | 전체 |
| 본인 진술 | 채널 소개·인터뷰 1건 | **+ 시청자 반응 샘플** | + 1:1 인터뷰 |
| 콘텐츠 샘플 | 최근 방송 1개 | 최근 3~5개 + 숏폼 | 시기별 샘플 |
| 수집 근거 | source_url·수집일 | raw snapshot + response_hash | 재현 가능한 run package |
| 카테고리 판정 근거 | 주 카테고리 1개 | category_basis + 상위 카테고리 비중 | 최근 90일/1년 카테고리 분포 |
| peak 기준 | raw max | max + p95 + median + recent_median | 스파이크/일상 체급 분리 |
| 시청자 수용 샘플 | 공개 반응 소수 | 익명화 반응 유형·어휘 | 세그먼트별 반응 패턴 |
| 외부 채널 데이터 | 게시일·조회수 | 게시 전후 팔로워/시청자 변화 | 콘텐츠별 전환 퍼널 |
| 실행 장벽 데이터 | 수행 여부 | 미이행 사유·부담 점수 | 액션별 장벽 패턴 |
| 부재 인벤토리 | 없음/미확인 구분 | absence_source 기록 | 재확인 이력 + 영향도 |

**최소 미만이면 P2(Deep-Dive)를 시작하지 말 것** *(v4.1 스코프 조정)*. 6개월 데이터로 시작하면 추세를 오판한다(§2 함정 참조). 이 최소 요건은 P2 기준이다 — P0/P1은 §0.9의 데이터 전제를 따르며, 부족분은 산출물에 범위 고지로 명시한다. v2에서는 “값이 없음”을 즉시 결론으로 쓰지 않고 `absent / unknown / not_collected`로 분리한다.

### 0.3 산출물 정의

한 케이스에서 만드는 기본 산출물은 다음 10종이다. v2부터 내부 산출물은 “결론 문서”뿐 아니라 **결론이 생긴 경로**를 남긴다.

| 산출물 | 대상 | 형식 | 단계 |
|---|---|---|---|
| project.json (레지스터) | 내부 | 의사결정 기록 | 전 단계 |
| 수집 근거 패키지 | 내부 | raw + meta + hash | §2 |

### 0.4 한 케이스 비용 추정 (v2 draft, 2 케이스 + 구비바 확장 기준)

- **분석 단계 (§0~§9):** 약 7~10 작업 세션 (1세션 = 집중 2~3시간)
- **실행 단계 (§10~§12):** 약 5~8 작업 세션 (시간 분산 — 클라이언트 실행 주기에 종속)
- **단계별 가중치:** §1·§2·§3·§5가 분석 비용의 약 50%
- **Stage별 가중치:** 입력 수집·분석 작업이 비용의 70%, 산출·실행 지원이 30%

⚠️ **사업화 관점에서 가장 중요한 미지수.** 분석 비용을 절반으로 줄여야 단가가 맞는다. v2 확장으로 수집·인벤토리 비용은 늘지만, 재현성·재사용성이 생겨 2회차부터 코호트 구축 비용을 낮출 수 있다. 실행 단계 비용은 *체크리스트·템플릿화*로 줄이기 가능.

### 0.5 사전 합의 표준 절차 *(v1 신설)*

**적용 대상:** 정식 의뢰 케이스. 친분 관계라도 *케이스 사용·익명화 사례 활용* 동의는 받음.

#### 0.5.1 합의 필요 영역 (4단계 분류)

| 단계 | 영역 | 처리 |
|---|---|---|
| 1단계 | 분석에 명확히 필요 | 공유 권장 |
| 2단계 | 사업 지속성 (재정) | **본인 선택** — 위치만, 액수 아님 |
| 3단계 | 자발 노출 시에만 | 직접 캐지 않음 |
| 4단계 | 받지 않음 | 자발 언급해도 기록·외부 공유 안 함 |

#### 0.5.2 합의 방식 두 형식

| 형식 | 적용 |
|---|---|
| (가) 공식 합의서 | 정중체·표준형 — 정식 의뢰 |
| (나) 평서체 합의 | 인터뷰 자연 흐름 — 친분 관계·무료 컨설팅 |

→ 두 형식 모두 *영역 분류 합의*가 핵심. 형식 자체는 상황에 맞춤.

#### ⚠️ 함정

- **합의 영역을 *분석가 시점*에서만 정함.** 공유 영역은 *최소 필수 + 본인 선택*으로 설계.
- **자발 노출을 *동의*로 착각.** 본인이 인터뷰 중 자발 발화한 정보가 *전부 공유 동의*는 아님. 민감 영역(재정·신원·관계 등)은 *별도 확인*.

#### 산출물

- 합의서 발송본 또는 합의 회신 기록
- project.json에 합의 영역 명시


### 0.6 공개·부분공개·비공개 태그 *(v3 신설)*

v3부터 모든 claim, 지표, 코호트, 산출물, 케이스 예시는 작성 시점에서 공개경계 태그를 가진다. 공개경계는 최종 배포 직전의 검열이 아니라, 분석·저장·전달·포트폴리오 변환 단계 전체에 붙는 운영 필드다.

| 태그 | 이름 | 의미 | 기본 처리 |
|---|---|---|---|
| 🟢 `green` | 공개 가능 | 일반 원칙, 추상 프레임, 공개 가능한 문제 정의 | 프리프린트·공개 데모에 사용 가능 |
| 🟡 `yellow` | 부분 공개 | 방법·개념은 공개 가능하지만 정확 값·도출 데이터·실제 케이스 근거는 비공개 | 공개 시 합성·범주화·값 제거 필요 |
| 🔴 `red` | 비공개 | 실제 클라이언트 데이터, 본인 고유 어휘, 민감 발화, 프롬프트, 임계 도출 근거, 운영 디테일 | 내부 보존. 외부 공개 금지 |

#### 0.6.1 기본 규칙

```text
무엇을/왜 = green 가능
어떤 개념으로 = yellow 가능
정확히 어떻게/얼마나/어떤 데이터로 = red 기본
```

#### 0.6.2 문서별 기본 태그

| 문서 | 기본 태그 | 설명 |
|---|---|---|
| 인터뷰 원문 | red | 본인 발화와 신원 단서 보존. 공개 금지 |
| §1 입력자료 | red | 본인 어휘·정체성 판단 포함 |
| project.json | red | 레지스터와 판단 근거 포함 |
| 내부 로드맵 | red | 실제 처방·반응 예측 포함 |
| 친근형 리포트 | red/client | 클라이언트 전달용. 공개 사례로 전환 금지 |
| 정식 리포트 | red/client 또는 yellow/internal | 외부 공유 가능성은 별도 검토 |
| CaseResult | red/internal | PortfolioRow 변환 전 원본 |
| PortfolioRow | red/internal 또는 yellow/internal | MCN 내부 row. 공개 전 축약 필요 |
| DecisionCard | red/internal | 사람 의사결정용 카드 |
| PublicDemoRow | green/yellow | 공개를 위해 처음부터 재작성한 객체 |

#### 0.6.3 공개 전 추가 질문

1. 이 정보는 `yellow` 영역인가? 방법·개념은 공개할 수 있지만 값·도출 데이터는 숨겨야 하는가?
2. 공개하지 않으면 학술 가치가 사라지는가? 그렇다면 익명화·합성·범주화로 학술 가치와 비식별성을 동시에 살릴 수 있는가?
3. 이 정보가 공개되면 클라이언트가 식별되는가?
4. 이 정보가 공개되면 사업 자산인 임계값·프롬프트·라우팅·검증 코호트가 드러나는가?

### 0.7 케이스 진행 단계 *(v1 신설)*

§§ 분석 단계와 *별도로*, 케이스 운영 측면의 진행 단계를 명시. 이 둘은 *겹치며 진행*된다.

#### 0.7.1 케이스 진행 6단계 (Stage)

```
[Stage A] 접촉·동의

[Stage D] 산출물 작성     — §9
[Stage E] 전달·반응
[Stage F] 실행 지원       — §10~§12
```

#### 0.7.2 클라이언트 응대 단계 (접점)

```
[접점 1] 의뢰·동의
[접점 2] 입력 수집 (자기소개·인터뷰)
[접점 3] 중간 미팅 (1차 발견 공유·정렬)
[접점 4] 후속 입력
[접점 5] 산출물 전달
[접점 6] 실행 지원·트래킹
[접점 7] 사후 응대 (장기 관계)
```

#### 0.7.3 Stage·접점 매핑

| Stage | 일반 접점 | 비고 |
|---|---|---|
| A | 접점 1 | |
| B | 접점 2 | 분석 자료 수집 |
| C | 접점 3 | 중간 발견 공유 — *생략 시 산출물 어긋남 위험* |
| D | (내부 작업) | |
| E | 접점 5 | |
| F | 접점 6·7 | 실행 단계 진입 |

#### ⚠️ 함정

- **§§ 분석 단계만 보고 *클라이언트 응대 단계 빠뜨림*.** 클라이언트는 *기다리는 입장*에서 *진행 상황 모름*. **클라이언트 응대 단계 별도 트래킹.**

### 0.9 실행 프로파일 — P0/P1/P2 *(v4.1 신설)*

이 방법론은 지금까지 Deep-Dive 풀코스 하나로 서술됐다. 그러나 실제 사업은 세 겹으로 돌아간다: 자동화 마이크로 진단(무료 훅) → 크몽 저가 상품 → 정식 Deep-Dive. §0.4의 비용 문제("분석 비용 절반 축소 필요")의 구조적 해답은 단계 생략이 아니라 **프로파일 분리**다.

#### 0.9.1 프로파일 정의 *(2026-07-09 가격·구성 개편 반영)*

| 프로파일 | 대응 상품 | 데이터 전제 | 세션 비용 |
|---|---|---|---|
| **P0 마이크로 진단** | 콜드메일 데이터 카드, 무료 사전확인, **무료 상담 (STANDARD 범위 선체험)** | **공개 데이터만** (본인 데이터 없음) | 자동화 (~0) + 상담 1회 |
| **P1 표준 진단** | 크몽 STANDARD 79k (축약 — 요약 보고서 1p) / **DELUXE 139k (full — 구비바 v4 전체 리포트 수준 + 수익구조 진단)** | 공개 데이터 + 본인 데이터 *권장* (없으면 명시 후 진행) | 1~3 세션 |
| **P2 실행형** | 크몽 PREMIUM 290k (DELUXE 전체 + 실행 우선순위 설계 + **주간 모니터링 4주 한정**) | P1 전제 + 실행 트래킹 협조 | 3~5 세션 + 체크인 4회 |
| **P2 Deep-Dive** | 정식 의뢰, MCN, 프리프린트 케이스 | §0.2 전체 (본인 일별 1년치 필수) | 7~15 세션 (현행) |

**퍼널 구조 (2026-07 확정)**: 무료 카드(P0) → 무료 상담(STANDARD 범위) → DELUXE 결제 유도. **파일럿 기간 한정, 초기 참여자에 한해 DELUXE 결제 시 PREMIUM 구성으로 제공** (정직 희소성 — "당신만 특별히" 화법 금지, 파일럿 프레임 사용. 업그레이드 제공 건은 기록에 upgrade=true 표기, 파일럿 종료 판단 입력). STANDARD는 앵커 티어 — 판매가 적어도 정상 작동.

#### 0.9.3 원칙

- **P0/P1의 정직성 의무**: 생략한 것을 숨기지 않는다. 산출물에 "본 진단은 공개 지표 기반이며 채널 내부 데이터(시청 지속·유입 경로)는 반영되지 않음" 급의 범위 고지를 명시한다.
- **기구축 코호트 자산이 P0/P1의 원가 구조다.** 코호트를 케이스마다 새로 만들면 P1 단가가 성립하지 않는다. 카테고리 전수 census(예: 버튜버 7,203 전수, 2026-07 구축)를 유지·갱신하는 것이 프로파일 체계의 전제.
- **P1 → P2 승격 기준**: 클라이언트가 본인 일별 데이터를 제공하고 실행 지원 범위를 원할 때. 승격 시 §0.8 전환 가능성 판정을 재실행.
- P0는 케이스가 아니다 — project.json을 만들지 않는다. P1부터 케이스 레지스터 생성.

#### ⚠️ 함정

- **P0/P1 산출물을 P2 품질로 오인시키는 문구.** "전수 분석" 같은 표현은 코호트에 대한 것이지 해당 채널 내부 분석이 아님을 구분.
- **P1에서 §5 함정들을 건너뛰기.** 프로파일이 얇아져도 함정(6개월 추세 단정 금지 등)은 그대로 적용된다. 프로파일은 범위 축소지 기준 완화가 아니다.

#### 산출물

- 케이스(P1+)의 project.json에 `profile: P0|P1|P2` 명시
- P0/P1 산출물 하단 범위 고지 문구


## 1. 정체성 추출

### 1.1 입력 자료

다음 세 가지를 균형 있게 수집한다.

| 층 | 출처 | 질문 |
|---|---|---|
| **본인 인식** | 채널 소개, 인터뷰, 본인 발화 | "본인이 자신을 뭐라고 정의하는가" |
| **콘텐츠 실제** | 최근 방송·숏폼 샘플 | "실제로 무엇을 하고 있는가" |
| **시청자 수용** | 채팅·댓글·반응 패턴 | "시청자가 무엇 때문에 보는가" |

### 1.2 추출 원칙 — 3층 일치점

세 층이 *겹치는 지점*이 진짜 정체성이다.

- 본인은 말하는데 콘텐츠엔 안 보임 → **희망사항** (정체성 아님)
- 콘텐츠엔 있는데 본인 인식 없음 → **잠재력** (확정 전)
- 시청자만 보는데 본인·콘텐츠에 없음 → **오해** (정체성 아님)
- **셋 다 있음 → 정체성 확정**

### 1.3 한 줄 포지셔닝 도출

3층 일치점을 한 문장으로 압축. 형식은 케이스에 따라 다름 — *반전 매력 + 관계 비유* 또는 *의도-수용 정합* 등. 형식 고집보다 *해당 케이스의 본질을 담는 형식*이 우선.

→ 케이스별 예시는 부록 E 케이스 간 비교 참조.

### 1.4 콘텐츠 진입/잔류 분리

정체성 위에서 콘텐츠의 두 기능을 명시.

- **진입(유입) 동력:** 시청자가 *처음 클릭*하는 이유 — 표면적·기능적
- **잔류(체류) 동력:** 시청자가 *남는* 이유 — 정서적·관계적

이 둘을 혼동하면 콘텐츠 전략이 흔들린다.

### 1.5 어휘 처리 원칙 *(v1 신설)*

본인 자발 어휘를 어떻게 보존·정제할지의 원칙. 어휘는 *정체성 표지*인 동시에 *분석 객관성*과 충돌할 수 있다.

#### 1.5.1 문서별 처리 원칙

| 문서 | 본인 어휘 처리 | 분석 진술 처리 |
|---|---|---|
| 인터뷰 원본 | 전부 보존 (변경 금지) | — |
| §1 입력자료 요약 | *본인 자발 어휘만* 따옴표로 보존 | 표준어 |
| project.json claim 본문 | 핵심 어휘 1~2개만 보존 | 나머지 표준어 |
| 한 줄 포지셔닝 | 핵심 어휘 그대로 (정체성 표지) | 연결 문장 표준어 |
| 정식 클라이언트 리포트 | 최소 인용 (따옴표 + "본인 표현" 명시) | 본문 표준어 |
| 친근형 클라이언트 리포트 | 어휘 톤 일부 차용 가능 | — |
| 익명화 사례 | 기능어로 치환 | 전부 표준어 |

#### 1.5.2 본인 자발 어휘 식별

본인 자발 어휘 = *본인이 직접 명명한* 어휘. 분석가 합성·번역이 아님. 자발 어휘는 *컨설팅 산출물·외부 채널 운영*에서 *그대로 활용 가능*.

#### 1.5.3 처리 우선순위

- 본인 어휘가 *결을 정확히 담음* → 보존
- 본인 어휘가 *분석 객관성 흐림* → 표준어 정제 (분석 진술에서)
- 충돌 시 → *문서 용도*에 따라 결정

### ⚠️ 함정

- **방송 제목·표면 표현을 정체성으로 착각.** 데이터 확인 없이 단정 금지 (부록 B 참조).
- **본인 진술만 받기.** 본인은 *되고 싶은 자기*를 말하는 경향. 시청자 반응과 콘텐츠 실제를 반드시 교차.
- **에디터 통합 해석을 *본인 명시 확인 없이* 확정 (v1 신규).** 추출 가설은 *본인 검증*을 거쳐야 확정 (부록 D 참조).
- **§1 단계에서 §6·§7·§9 발화 자연 발생을 *§1로만 묶어두기* (v1 신규).** 정식 의뢰·외부 피드백 부재 클라이언트에서 자주 발생. *§1 입력자료와 별도로 §6·§7·§9 진입 자료를 따로 정리*하여 후속 분석에 연결.

### 산출물

- 한 줄 포지셔닝 문장 1개
- 진입/잔류 동력 정의
- 3층 입력 자료 요약 노트

### 2.2 코호트 모집단 데이터

대상 채널의 카테고리에서 **상위 2,000명 랭킹**을 확보한다.

- 최소 컬럼: 채널명, 방송시간, 최고시청자, 평균시청자, 뷰어십
- 카테고리: 대상 채널의 *주 카테고리* 기준 (최근방송 1개로 판정하면 노이즈 큼 — 카테고리 분포 확인 후 결정)

코호트 채널들의 *팔로워 수*는 모집단 랭킹에 안 들어있을 수 있다. **별도 팔로워 랭킹**(상위 6,000위) 데이터를 매칭한다.

### 2.4 데이터 검증 절차

받자마자 다음 5가지 확인. **하나라도 안 맞으면 다음 단계 진행 금지.**

1. **기간 완전성** — 누락일 없는가, 끝일이 최신인가
2. **이상치** — 최고시청자가 평균시청자보다 작은 경우 등
3. **방송시간 분포** — 0.1h 미만·24h 이상 빈도 확인
4. **카테고리 일관성** — 대상이 모집단 카테고리와 정말 맞는가
5. **본인 데이터 ↔ 모집단 데이터** — 같은 채널의 수치가 양쪽에서 일치하는가

### 2.5 수집 근거와 재현성 스키마 *(v2 신설)*

## 3. 측정 보정 — 노방종/장시간 효과

### 3.1 평균 시청자 왜곡 원리

**평균 시청자 = 총 시청량 ÷ 방송 시간.** 방송시간이 길어지면 (시청자 적은 새벽·심야 시간 포함) 분모가 팽창하여 평균이 *기계적으로* 깎인다. *수요 감소 아님, 측정 효과.*

### 3.2 노방종 식별 기준

- **임계:** 하루 방송시간 14시간 이상
- **상습 판정:** 1년에 5일 이상 14h+ 또는 par(방송시간/평청) > 4

이 기준에 걸리는 *날*과 *채널*을 별도 표시한다.

### 3.3 보정 방식 (택1 또는 병용)

| 방식 | 계산 | 장점 | 단점 |
|---|---|---|---|
| **A. peak 비율법** | 보정평청 = 최고시청자 × 0.62 (정상채널 중앙비율) | 단순, 노방종 robust | 단발 spike에 취약 |
| **B. 시간가중 평균** | Σ(평청×시간) ÷ Σ시간 | 정밀, 분기 비교 강함 | 채널 단위 적용 시 분모 한쪽으로 작용 |
| **C. 노방종 제외 평균** | 14h+ 날 제외하고 단순 평균 | 직관적 | 데이터 손실 |

**권장:** 채널 단위 비교(코호트) → A. 시계열 분석 → B. 그래프용 → C.

### 3.4 권장 지표 체계

이후 모든 분석에서 다음 우선순위 적용.

| 순위 | 지표 | 용도 |
|---|---|---|
| 1 | 최고 시청자 (peak) | 노방종 robust 규모 지표 |
| 2 | 채팅 (6분 평균) | 코어 참여도 |
| 3 | 보정 평균 시청자 | 비율 산정 |
| 보조 | 원시 평균 시청자 | 단독 사용 금지 |

### 3.5 노방종 0일 케이스 처리 *(v1 신설)*

대상 채널이 1년 중 노방종 0일인 경우, §3 보정이 *거의 미적용*되는 케이스.

#### 처리 방식

- **§3 보정 자체는 *통과* 처리.** 보정 효과 없음. 다만 *원시 평균을 그대로 쓸 수 있다는 확인 자체*가 §3의 산출물.
- **권장 지표 체계는 그대로 적용.** peak 1순위, 채팅 2순위, 평청은 *원시 그대로* 사용 가능.
- **§5.5 보정 견고성도 *통과*.** 원시 = 보정이므로 자동 견고.

#### 함의

- 노방종 0일 케이스는 *§3 부담이 낮음*이라 케이스 비용 감소
- 그러나 *§3 함정*은 여전히 점검: 본인이 *향후 노방종 시도 의향* 있는지, 코호트에 *노방종 채널 비중*이 어떻게 되는지

### ⚠️ 함정

- **특정 시기 평청 급락을 진단으로 받기.** 평청 변동 → 먼저 *그 시기 방송시간 분포* 확인 (부록 B 참조).
- **노방종을 "전략"으로 무비판 수용.** 노방종이 *실제 효과 있는지*는 측정해야 한다.
- **보정값 한 가지로 단정.** *원시·보정 양쪽 제시*하고 보정 안 해도 결론이 유지되는지 확인.
- **노방종 0일 케이스에서 §3 자체를 건너뛰기 (v1 신규).** §3은 *생략*이 아니라 *통과 확인*. 산출물에 "노방종 0일 확인, 보정 미적용" 명시.

### 산출물

- 노방종 식별된 날 목록 (또는 "노방종 0일 확인" 명시)
- 코호트 내 노방종 채널 목록
- 보정값 적용된 채널별 지표 표 (또는 "보정 미적용" 명시)

## 4. 코호트 구축

### 4.1 동급 정의

**peak 기준이 기본.** 팔로워는 누적·휴면 포함이라 현재 라이브 규모와 어긋난다. peak가 실시간 규모의 직접 측정.

- **동급 범위:** 대상 채널 peak의 0.5배 ~ 2.0배

### 4.2 필터 단계

```
모집단 (카테고리 상위 2,000명)
  ↓ peak 0.5~2.0배 필터
1차 후보 (~200명)
  ↓ e스포츠팀·대회·기업 운영 계정 제외
2차 후보 (~190명)
  ↓ 팔로워 매칭 (별도 데이터)
3차 후보 (~150명)
  ↓ 명백한 이상치 제외 (휴면·신생 1~2개월 미만 등)
최종 코호트 (~130명)
```

### 4.3 포함 결정 — 경계 케이스

다음 케이스는 *표면으로 배제 금지.* 데이터로 확인 후 결정.

| 경계 케이스 | 점검 방법 | 판정 |
|---|---|---|
| 버추얼 채널 | 비-버추얼과 비율·충성도 분포 비교 | 분포 겹치면 포함, 명확히 다르면 분리 |
| 다른 게임 부주력 | 카테고리 분포 (방송 일수) | 주력 일치하면 포함 |
| 매우 작은 채널 | peak 하한 미만이면 별도 | 별도 |

### 4.4 강건성 검증 (필수)

코호트 결론을 확정하기 전에, **필터 조건을 바꿔도 대상 채널 위치가 유지되는지** 확인한다.

| 추가 필터 | 점검 의미 |
|---|---|
| 방송시간 10h+ / 20h+ / 30h+ 만 | 짧은 방송 채널의 비율 뻥튀기 우려 해소 |
| 카테고리 단일 (대상 채널 카테고리만) | 다른 게임 노이즈 제거 |
| 비-버추얼만 | 종족 차이 우려 해소 |
| 비-노방종만 | 노방종 보정 의존도 점검 |

**모든 필터에서 대상 채널이 상위권 유지하면 → 결론 강건.** 한 필터라도 위치가 크게 흔들리면 → 그 요인을 깊이 분석.

#### 4.5 이전 케이스 자산 재활용 + 상설 카테고리 census *(v1 보강, v4.1 확장)*

새 케이스 진입 시, *이전 케이스의 코호트 데이터*가 적용 가능한지 먼저 점검. 적용 가능하면 데이터 수집 비용 감소.

- 점검 방법: 이전 케이스 코호트의 peak 범위·카테고리·플랫폼 결과 비교
- 적용 불가 시: 새 모집단 수집

**상설 카테고리 census** *(v4.1 신설)*: §0.9의 P0/P1 원가구조는 케이스마다 모집단을 새로 수집하는 것이 아니라, **카테고리 전수 census를 미리 구축·갱신해 재사용**하는 것을 전제한다. 이 경우 §4.2 필터 단계의 "모집단 수집"이 이미 완료된 상태에서 시작한다.

- 예: 치지직 버튜버 전수 census 7,203채널(2026-07 구축, 팔로워·지표 보강 완료)을 버튜버 케이스의 모집단으로 상시 재사용.
- 갱신 주기: 주간 스냅샷(수집 로드맵 Phase C)으로 시계열까지 축적하면 §6.6 궤적매칭의 t0 탐색 자산이 됨.
- 카테고리별로 census가 없는 신규 영역은 §4.2대로 새 모집단을 수집하며, 이때는 P1 단가가 성립하지 않아 P2로 취급한다.

### 4.6 카테고리 판정 신뢰도 *(v2 신설)*

카테고리는 최근 방송 1건으로 확정하지 않는다. 가능하면 최근 90일 또는 1년의 카테고리 분포로 판단한다.

권장 컬럼:

```csv
primary_category,category_basis,category_1,category_1_share,category_2,category_2_share,category_3,category_3_share,is_general_game,general_game_basis,is_virtual,virtual_basis,category_confidence
```

| 신뢰도 | 조건 |
|---|---|
| high | 주 카테고리 비중이 높고, 프로필/방송 이력/외부 랭킹이 일치 |
| medium | 주 카테고리는 보이나 일부 혼합. 보조 코호트 필요 |
| low | 최근 방송·프로필·랭킹이 불일치. 수동 검토 필요 |

### 4.7 peak 기준 다중화 *(v2 신설)*

동급 정의는 여전히 peak 0.5~2.0배가 기본이다. 단, `raw max peak` 하나만 쓰면 레이드·이벤트·일회성 스파이크에 끌려갈 수 있다.

대상 채널과 코호트 모두 다음 peak를 보존한다.

```csv
peak_max,peak_p95,peak_median,peak_recent_median,peak_recent_p95
```

| 기준 | 용도 |
|---|---|
| `peak_max` | 외부 랭킹·최대 동원력 대응 |
| `peak_p95` | 극단 스파이크 완화 |
| `peak_median` | 일상 체급 |
| `peak_recent_median` | 현재 체급 |
| `peak_recent_p95` | 최근 스파이크 포함 현재 체급 |

코호트 필터 결과는 다음처럼 따로 남긴다.

```csv
within_band_by_max,within_band_by_p95,within_band_by_median,within_band_by_recent_median
```

### 4.8 주 코호트·보조 코호트 운영 *(v2 신설)*

경계형 채널은 코호트를 하나로 강제하지 않는다. **주 코호트**는 본문 결론에 쓰고, **보조 코호트**는 결론 강건성 검증에 쓴다.

| 구분 | 용도 |
|---|---|
| 주 코호트 | 대상 채널의 기본 시장 위치 판단 |
| 보조 코호트 | 버추얼/비버추얼, 단일게임/종합게임 등 경계 요인의 영향 확인 |
| robustness only | 본문 결론으로 쓰지 않고 흔들림 여부만 확인 |

보조 코호트에서 결론이 크게 흔들리면, 본문에 “시장 정의에 따라 결론이 달라진다”고 명시한다.

#### 4.8.1 보조 코호트가 주가 되는 경우 *(v4 신설)*

대상 채널의 특성이 기본 모집단(카테고리 랭킹)보다 보조 코호트와 더 정확히 일치하면, 보조 코호트가 주 분석 대상이 된다.

예: 버추얼 스트리머 → 카테고리 전체(general_game) 2,000명이 아니라 버추얼 전수(576명)가 주 코호트. general_game은 교차검증용.

**판정 기준:**

- 대상 채널이 보조 코호트에서 분포 중심에 가깝고, 기본 코호트에서는 분포 변두리에 있을 때
- 보조 코호트의 코호트 내 CV(변동계수)가 기본 코호트보다 낮을 때 (더 균질)
- 대상 채널의 자기 정체성(§1)이 보조 코호트의 정의와 직접 일치할 때

**역전 시 처리:**

- 보조 코호트를 §5 본문 분석 대상으로 쓴다
- 기본 코호트(원래 주 코호트)는 교차검증·외삽 용도로 유지한다
- 역전 결정을 project.json에 기록하고, 코호트 방법론 MD에 명시한다

### ⚠️ 함정

- **카테고리·버추얼을 직관으로 배제.** 분포 확인 후 결정 (부록 B 참조).
- **모집단 카테고리 오인.** 모집단이 "롤 카테고리"인지 "치지직 전체"인지 명확히. 외삽 함부로 금지.
- **peak 상한 편향.** peak 240 상한으로 자르면 *큰 채널의 비율*이 누락. 결론에 영향 없는지 점검.

### 산출물

- 코호트 명단 CSV (전 컬럼 + 보정값 + 플래그)
- 코호트 구성 방법론 MD (재현 가능하도록)
- 주 코호트·보조 코호트 결정 기록
- 카테고리 판정 신뢰도 표
- peak 기준별 강건성 검증 표

## 5. 6단계 진단 분석

### 5.1 기술 통계

코호트의 *분포부터* 본다. 단일 채널 위치 보기 전에 모집단을 안다.

- 비율 분포 (히스토그램·분위수)
- 팔로워 분포
- peak 분포
- 방송시간 분포

#### 5.1.2 코호트 레이어 분할 *(v4 신설)*

기술통계 후 코호트를 3개 레이어로 나눈다.

| 레이어 | 정의 | 용도 |
|---|---|---|
| A (동체급) | 대상 채널 peak의 ±50% | 가장 직접적인 비교군 |
| B (동급) | §4 기준 0.5x~2.0x | §5 본문 분석 대상 |
| C (나머지) | B 밖 전체 | 분포 맥락·외삽 검증 |

레이어별 기술통계를 따로 보고, robustness table에 반영한다.

##### robustness table 구조

4 layer × N metric 테이블. layer = A, B, C, B+C 확장.

| layer | n | metric_1 %ile | metric_2 %ile | ... |
|---|---|---|---|---|

이 테이블의 목적: 대상 채널의 위치가 레이어 정의에 따라 흔들리는지 확인. B에서 상위 30%인데 A에서 하위 50%이면 → 체급 민감도가 높다는 신호.

### 5.2 대상 채널 다축 위치 *(v4 재작성: 4축→6축)*

6축으로 본다. 어느 축에서나 상위 25% 이상이면 강점, 하위 25% 이하면 약점.

| 축 | 지표 | 의미 |
|---|---|---|
| 전환율 | 팔로워 대비 평균 시청자 비율 | 효율 — 적은 팔로워로 많이 모으는가 |
| 피크 | 최고 동시 시청자 | 절대 규모 — 천장이 어디인가 |
| 효율 | 방송시간 대비 시청자 | 시간 투입 대비 산출 |
| 잔류율 | 평균 시청자 / 최고 시청자 | 방송 *내* 이탈 — 한 방송 동안 사람이 남는가 |
| 방송시간 | 누적 방송 시간 | 활동 강도 |
| 팔로워 | 팔로워 수 (작은순 순위) | 체급 |

#### 5.2.1 잔류율 vs 리텐션 구분 *(v4 신설, v4.1 직접/프록시 분리)*

이름이 비슷해서 혼동하기 쉬운 두 지표를 구분한다.

| 지표 | 범위 | 수식 | 해석 |
|---|---|---|---|
| **잔류율** (within-broadcast) | 0~1 | avg_viewers / peak_viewers (방송 1회 단위) | 한 방송 안에서 시청자가 얼마나 남는가. 높으면 이탈이 적다. |
| **리텐션_직접** (between-broadcast) | 0~1 | 돌아온 시청자 / 이전 방송 시청자 | 방송 *간* 복귀율. 높으면 습관 시청이 강하다. |
| **리텐션_프록시** *(v4.1 신설)* | 0~1 | 기간 집계 avg / 기간 집계 peak (예: 45일 창) | 피크 대비 일상 유지 수준. 복귀율의 간접 신호. |

**핵심:** 잔류율과 리텐션은 독립적이다. 잔류율이 높아도 리텐션이 낮을 수 있고, 그 반대도 성립한다.

**직접/프록시 구분이 필요한 이유** *(v4.1)*: 리텐션_직접은 시청자 단위 추적을 요구하는데, 이는 공개 데이터로 불가능하고 §2.7(개인정보 최소화)이 시청자 개별 추적을 금지한다. 본인 제공 데이터에 복귀율이 있는 경우(P2)에만 직접 측정이 가능하다. 그 외에는 리텐션_프록시를 쓴다.

**리텐션_프록시의 유효 조건과 한계:**

- 측정 창은 30~60일 (짧으면 스파이크 1건에 좌우, 길면 추세 변화가 섞임). 창 길이를 산출물에 명시한다.
- 프록시가 낮다 = "최고 방송 대비 일상 방송이 낮다"이며, 이는 ①복귀 저조 ②스파이크 의존 ③편성 불규칙이 섞인 신호다. **복귀율 그 자체가 아니다.**
- 산출물에는 반드시 "프록시" 표기와 수식을 병기한다. 잔류율(방송 1회 단위)과 측정 단위가 다름을 명시한다.

*실전 사례 (구비바):* 잔류율 0.712 (코호트 상위 14%) vs 리텐션_프록시 27% (45일 창, 코호트 하위 25%). 한 방송 안에서는 사람이 잘 남지만, 최고 방송 대비 일상 방송 수준이 낮다. → 스파이크 시청자가 일상 방송으로 돌아오지 않는 구조를 시사 (직접 복귀율은 미측정).

### ⚠️ 5.2 함정 *(v4 신설, v4.1 갱신)*

- **잔류율이 높으면 리텐션도 높을 것이라는 착각.** 두 지표의 상관은 코호트마다 다르다. 반드시 둘 다 측정하라.
- **리텐션 데이터가 없으면 잔류율로 대체.** 대체 불가. 잔류율은 방송 *내* 지표다. 복귀 신호가 필요하면 리텐션_프록시를 쓰되 프록시임을 명시하라.
- **프록시를 직접 측정처럼 서술 (v4.1 신규).** "복귀율 27%"라고 쓰면 오서술이다. "피크 대비 일상 유지율(프록시) 27%"로 쓴다. 실전에서 실제로 발생했던 오서술 패턴이다.

### 5.3 동질성 확인

코호트가 정말 *동질 집단*인가? 대리지표로 결속력을 본다.

- **par (방송시간/평청):** 4 이상이면 노방종형, 분포 확인
- **충성도 (peak/평청):** 1.5~3 정상, 그 이상이면 단발 spike

### 5.4 핵심 관계 정량화

대상 채널이 도달하려는 목표(예: 1만 팔로워)와 현재 강점(예: 비율)의 관계를 *코호트 데이터로* 계산.

- 팔로워 vs 비율 상관 (log-log)
- 팔로워 구간별 중앙 비율
- 회귀 또는 분위수 추정

#### 5.4.2 편상관(partial correlation) 검증 *(v4 신설)*

단순 상관이 유의하면, 교란 변수를 통제한 편상관을 추가로 확인한다.

**권장 통제 변수:** 방송 일수, 방송 시간

**방법:**

1. 단순 Pearson r 계산 (예: 팔로워 vs 비율)
2. 통제 변수를 넣고 편상관 r 계산
3. 비교

| 조건 | 단순 r | 편상관 r | 해석 |
|---|---|---|---|
| 두 r 모두 유의, 크기 유지 | +0.761 | +0.756 | 실제 관계. 교란 효과 미미. |
| 단순 r 유의, 편상관 r 급감 | +0.761 | +0.15 | 허위 상관. 통제 변수가 진짜 원인. |
| 두 r 모두 비유의 | — | — | 관계 없음. |

*실전 사례 (김달수):* 팔로워 vs 비율의 단순 r=+0.761, 방송 일수 통제 후 편상관 r=+0.756. → 방송 일수는 교란 요인이 아니며, 팔로워-비율 관계는 실질적.

**함정:** 통제 변수를 3개 이상 넣으면 자유도가 급감한다. 코호트 규모가 100 미만이면 통제 변수는 1~2개로 제한하라.

## 6. 목표 트레이드오프 정량화

### 6.1 상충 식별

대상 채널의 *목표*(예: 1만 팔로워, 평청 100 등)와 *현재 강점 지표*(예: 비율) 사이에 충돌이 있는가? 코호트 데이터로 확인.

### 6.2 상위 참조 밴드 프로토콜 *(v4 재작성)*

기존 "도달 가능 범위 추정"을 구체화한다. 코호트 *내* 회귀만으로는 체급 상승 비용을 알 수 없다. 대상 채널보다 *위* 체급의 실제 데이터를 수집해서 갭을 직접 측정한다.

#### 6.2.1 상위밴드 수집

대상 채널 팔로워 수 기준으로, 그 위 밴드의 채널을 추가 수집한다.

| 밴드 | 팔로워 구간 | 최소 채널 수 | 용도 |
|---|---|---|---|
| 현재 밴드 | 대상 채널 ±50% | §5에서 이미 확보 | 현재 위치 확인 |
| 중간 밴드 | 현재 상한~2x | 20+ | 다음 단계 비용 추정 |
| 목표 밴드 | 목표 팔로워 ±50% | 20+ | 목표 도달 비용 확인 |

*실전 사례:* 구비바(팔로워 12K) → 10K-20K(현재), 20K-50K(중간), 50K+(목표) 총 271채널 수집.

**수집 원칙:** 같은 플랫폼·카테고리·지역에서 수집한다. 다른 플랫폼 채널을 섞지 않는다.

#### 6.2.2 갭 측정

6축(§5.2) 각각에 대해, 밴드별 중앙값과 대상 채널의 차이를 계산한다.

| 지표 | 대상 채널 값 | 현재 밴드 중앙값 | 중간 밴드 중앙값 | 목표 밴드 중앙값 | 갭 비율 |
|---|---|---|---|---|---|
| 전환율 | — | — | — | — | — |
| 피크 | — | — | — | — | — |
| 효율 | — | — | — | — | — |
| 잔류율 | — | — | — | — | — |
| 방송시간 | — | — | — | — | — |
| 팔로워 | — | — | — | — | — |

갭 비율 = (목표 밴드 중앙값 - 대상 채널 값) / 대상 채널 값. 가장 큰 갭이 1차 병목.

#### 6.2.3 병목 식별 + 시간 추정

갭 비율이 가장 큰 지표가 1차 병목이다. *(v4.1: "P0"는 §0.9에서 프로파일 이름으로 예약됨 — 우선순위 병목은 "1차 병목"으로 표기한다.)*

**시간 추정 방법:** 대상 채널의 최근 6개월 성장률로 1차 병목 지표가 목표 밴드 중앙값에 도달하는 시점을 외삽한다.

**전환율 역전 경고:** 체급이 올라가면 전환율은 *구조적으로 하락*한다 (팔로워 모수 증가). §6.1 상충 식별과 연결. 팔로워 성장과 전환율 유지를 동시에 목표로 잡으면 비현실적.

#### 6.2.4 기존 방식과의 관계

기존 코호트 회귀 방식(v3의 §6.2)은 폐기가 아니라 보조로 유지한다.

- **A방식 (구간별 중앙값):** 밴드 프로토콜의 6.2.2와 동일. 방향 확인용.
- **B방식 (log-log 회귀):** 밴드 경계를 넘는 외삽에서 쓴다. 방향 확인용.
- **밴드 프로토콜:** 실제 거리를 측정한다. A·B는 방향, 밴드 프로토콜은 거리.

두 방식의 차이가 크면 *불확실 범위*로 양쪽 제시한다는 원칙은 유지.

### 6.3 권장 목표 + 경보 하한선

- **권장 목표:** 코호트 동급에서 *현실적 상위권*에 해당하는 수치
- **경보 하한:** 그 이하로 떨어지면 "성장이 진성으로 전환 안 됨" 신호

#### 6.3.1 리텐션 하한 경보 *(v4 신설, v4.1 프록시 반영, 2026-07-08 백테스트로 L2 강등)*

전환율·피크의 경보 외에, **리텐션**에도 하한을 설정한다. 사용하는 리텐션 지표는 §5.2.1의 세 정의 중 데이터 가용성에 따라 정한다.

- 코호트 하위 25% 리텐션값을 경보 하한으로 쓴다. **어떤 리텐션 지표(직접/프록시)를 썼는지 경보에 함께 표기한다.**
- 리텐션_직접이 없는 코호트에서는 **리텐션_프록시(기간집계 avg/peak)로 대체 가능** *(v4.1 조정)*. 단 프록시임을 명시하고, 프록시조차 산출 불가하면 "측정 불가"로 명시한다. 잔류율(방송 내 지표)로는 대체하지 않는다 (§5.2.1 참조).
- **예측 주장 금지 (백테스트 기각, §8.6.4):** 프록시 기반 하한 미달이 이후 성장 정체를 예측한다는 근거는 없음이 확인됐다. 이 경보는 "현재 상태의 이상 신호"(진단 트리거)로만 쓰고, "모래 위의 성장" 같은 미래 단정 문구는 클라이언트 산출물에서 쓰지 않는다. 미래 전망은 §6.3.2 성장 전망 신호를 쓴다. 리텐션_직접(P2, 본인 데이터) 기반 경보는 백테스트 대상이 아니었으므로 이 강등의 적용을 받지 않되, 역시 L3 이상을 주장하려면 별도 검증이 필요하다.

#### 6.3.2 성장 전망 신호 — 효율×관성 *(2026-07-08 신설, 패턴 마이닝 재현 검증 기반, L3)*

999채널×53주 데이터의 역추출에서 **재현 검증을 통과한** 전방 신호. 리텐션 하한 경보가 하려던 "위험 채널 조기 식별"을 실증된 조합으로 대체한다.

**정의 (모두 세그먼트 코호트 내 percentile, t 시점까지 정보만):**
- **뷰어십 효율** = 평시청(avgLiveViews) / 팔로워. "보러는 오는데 아직 팔로우 안 누른 인구"의 크기.
- **성장 관성** = 직전 4주 팔로워 상대 성장률.

**판정표 (검증 스냅샷 실측, n=639, 기저 49.3%):**

| 신호 | 조건 | P(이후 12주 초과 성장) | 해석 |
|---|---|---|---|
| 청신호 | 효율 상위 25% AND 관성 상위 25% | 90.0% (n=80) | 성장 구간 진입 — 지금이 투자(콘텐츠·노출) 적기 |
| 준청신호 | 관성만 상위 25% | 87.8% (n=82) | 흐름은 왔으나 효율 낮으면 전환 손실 점검 |
| 중립 | 그 외 | ~기저 | 6축 진단으로 병목 특정 |
| 적신호 | 효율 하위 25% AND 관성 하위 25% | 6.8% (n=74) | 정체 지속 가능성 높음 — 구조 개입 필요 신호 |

**사용 규칙:**
- claim_level **L3(패턴 상관)**. 인과 화법 금지 — "효율을 올리면 성장한다"가 아니라 "이 상태는 성장에 선행하는 패턴"으로만 서술한다.
- 발굴·검증이 동일 모집단(버튜버 999)의 시간 분할이므로, **분기마다 신규 데이터로 재백테스트**한다(`tools/backtest` growth_outlook 규칙, §8.6). 재백테스트 실패 시 즉시 L2 강등. *(2026-07-09 전수 7,472 재검증: 판정 동일, 청 55.8%/적 7.4% — §8.6.4)*
- 버튜버 외 카테고리 적용 시 "타 코호트 미검증" 표기 의무.
- 근거: `runs/pattern_mining_20260708/mining_results.json` (시간분할 설계·수치), §8.6.4.

### 6.4 영속 의향형 케이스 처리 *(v1 신설)*

본인이 *졸업 의지 없음 + 축소되더라도 계속* 영속 의향인 경우, *권장 목표*가 *도달점*이 아닌 *통과점*이 됨. 다음 두 질문 추가.

#### 두 결정 질문

1. **임계점 도달 vs 미달 지속 선택** — 목표를 *방송 수입 임계점 도달*로 잡을지 *임계점 미달 지속 가능 구조*로 잡을지. 단순 선택 아닌 *시간 축 분리* 가능 (단기 도달 / 장기 안정).
2. **데드라인 vs 영속 흡수** — 권장 목표(예: 1만)를 *데드라인형*(언제까지)으로 잡을지 *영속 흐름 안 통과점*으로 흡수시킬지.

→ 본인 답이 둘 중 하나로 정해지면 §6 권장 목표 형식 결정.

#### 영속 의향 식별 신호

본인 인터뷰에서 다음 발화 패턴 발현 시 영속 의향형 분류:

- "졸업 생각 안 함" 또는 동등 진술
- "축소되더라도 계속" 또는 동등 진술
- "본업 잡아도 계속" 또는 동등 진술
- 데드라인 질문에 *없다·따로 없다* 답

### 6.5 수익·후원 수용성은 금액보다 장벽 중심 *(v2 신설)*

수익·후원 영역은 민감하다. 정확한 금액·후원자·개인별 내역보다, 본인이 **후원을 요청하거나 수용할 수 있는가**를 중심으로 기록한다.

권장 컬럼:

```csv
date,context,donation_feature_enabled,support_cta_present,donation_mention_count,creator_acceptance_score,viewer_survey_done,viewer_acceptance_rate,main_objection,action_limit,next_test,privacy_level
```

원칙:

- 본인이 자발 공유한 금액도 외부 산출물에는 범주화한다.
- 후원자 개인 식별 정보는 저장하지 않는다.
- “돈을 더 받아라”가 아니라 “후원을 콘텐츠·운영 구조 안에서 받아들일 수 있는가”를 본다.
- 시청자 설문은 자발 참여형으로 설계하고, 개별 응답자를 추적하지 않는다.

### ⚠️ 함정

- **목표 고정값 유지 가정.** "현재 비율을 1만에서도 유지"는 거의 불가능. *체급 상승 비용*을 인정한 목표가 현실적.
- **이분법 함정.** "비율 vs 규모, 택일"이 아니라 *어느 비율대를 지키느냐*가 진짜 질문.
- **본인 영속 의향 무시하고 표준 목표 적용 (v1 신규).** "1만 1년 안에 도달" 같은 표준 형식이 *영속 의향*과 어긋날 수 있음. 본인 인터뷰에서 *졸업·축소·영속 의향*을 확인하고 §6에 반영.

### 6.6 궤적매칭 — 시점 정렬 코호트 *(v4.1 전면 재작성)*

대상 채널의 *미래*를 추정할 때, 코호트 평균이 아니라 유사 과거 궤적을 가진 채널을 참조한다.

**v4 → v4.1 폐기 근거.** v4의 비전/피어 가중 스코어링 방식은 검수에서 결함 8건이 확인되어 폐기한다: ①매칭과 벤치마크 목적 혼동(대상 기울기보다 훨씬 빠른 채널만 상위로 뽑힘) ②시점 정렬 부재 ③시장 베타 미조정(플랫폼 성장기라 전원 기울기 부풀려짐) ④생존·선택 편향(성장 채널만 표본 → 낙관 편향) ⑤짧은 창+정수 노이즈 ⑥가중치 임의성(체급 점수 제거 시 순위 전복 = 가중 스코어가 순위를 지배한다는 증거). 상세 재설계: `specs/trajectory_matching_v3_spec_20260707.md`.

**명칭 규칙.** 이 방식은 "Synthetic Control"이 아니다(SC는 여러 대조 채널의 가중 조합으로 반사실 궤적을 만드는 방법). "시점 정렬 코호트" 또는 "궤적 매칭"으로만 부른다.

#### 6.6.1 세 트랙 — 목적을 분리한다

| 트랙 | 이름 | 질문 | 산출 |
|---|---|---|---|
| **C** (앵커, 필수) | 통과자 분포 | 대상 레벨을 지난 채널들은 그 후 어떻게 됐나 | 상승/정체/하락 비율 (h=3, 6개월) |
| **A** | 동행 채널 | 대상과 같은 속도로 가는 채널들의 다음 구간은 | 예측 밴드 (동행들의 t+3~6 분포) |
| **B** | 언니 채널 | 레벨 통과 후 상승한 채널은 무엇을 달리했나 | 벤치마크 사례 + 행동 차이 |

**리포트 게이트: Track C 없이 Track B만 싣는 것을 금지한다.** 성공 사례(언니)만 보여주면 낙관 편향이 된다. 반드시 통과자 전체의 상승/정체/하락 분포(현실)를 먼저 제시하고, 사례는 그 위에 얹는다. (§9 클라이언트 리포트 원칙에도 연결.)

#### 6.6.2 시점 정렬 (t0)

"언니"의 정의는 "같은 길을 먼저 간 채널"이다. 따라서 후보의 **대상 현재 레벨 L 통과 시점**을 t0로 잡고, 그 이후 궤적을 본다.

- **t0 정의:** 채널의 3개월 이동중앙값이 L(대상 채널 현재 3개월 중앙값)의 ±10% 밴드에 처음 진입한 월. 이동중앙값을 쓰는 이유는 정수 반올림·단발 스파이크로 인한 가짜 통과 방지.
- t0가 후보의 관측창 안에 없으면 **탈락**시킨다. (기준을 완화해 n을 늘리는 것보다 정직한 소표본이 낫다 — v4가 ratio 1.1~5.0x로 완화한 방향은 거꾸로였다.)

#### 6.6.3 시장 조정 기울기 α

치지직 전체가 성장기다(평균 시청자 +39.9% YoY, 실측). 최근 창에서 기울기를 그대로 재면 전원이 플랫폼 상승분만큼 부풀려진다.

```
α_ch(w) = slope_ch(w) − median{ slope_j(w) : j ∈ 동급 밴드(±50%) 코호트, 같은 캘린더 창 w }
```

같은 달력 기간의 동급 중앙 기울기를 빼서 플랫폼 베타를 제거한다. **모든 성장 판정은 raw slope가 아니라 α 기준.**

#### 6.6.4 트랙별 알고리즘 (가중 점수 없음 — 필터 + 단일 정렬)

v4.1은 100점 가중 스코어를 폐기한다(⑥ 결함). 각 트랙은 필터 통과 후 단일 기준으로 정렬한다.

**Track C (먼저 실행 — 모든 해석의 앵커):**
```
전수 풀 → 시계열 6mo+ → t0 존재 → t0+h개월 후 분류
분류(3개월 이동중앙값 변화율): 상승 +20%↑ / 정체 ±20% / 하락 −20%↓
출력: n, 상승 X% / 정체 Y% / 하락 Z% / 미성숙 k개 (h=3·6 둘 다)
```

**Track A (동행):**
```
필터: 현재 레벨 0.7~1.5 × L  AND  |α_ch − α_대상| ≤ 0.3/월  AND  CV ≤ 0.25
정렬: 정규화 궤적 간 RMSE 오름차순 → 상위 10
      (정규화 = 궤적을 창 시작값으로 나눔. 거리 함수는 RMSE 단일 — DTW·상관 혼합 금지)
출력: 동행 10개의 다음 3~6개월 실제 궤적 분포 = 대상 예측 밴드
```

**Track B (언니):**
```
필터: t0 존재  AND  t0+h에서 "상승" 분류
정렬: α 내림차순 → 상위 10 (사례 소개는 3~5)
확장(데이터 있을 때): 상승 그룹 vs 정체 그룹의 관측 가능 행동 차이
  (방송시간 변화·편성 규칙성·카테고리 전환 — §5.7 편성, §7 콘텐츠 데이터)
```

#### 6.6.5 노이즈 처리와 검증

- 정수 반올림: 각 관측값 ±0.5 균등 노이즈로 slope 부트스트랩(1,000회) → **slope 95% CI**. CI가 겹치는 채널 간 순위 차이는 결론에 쓰지 않는다.
- 4~5개월 창은 CI가 커서 자연 탈락 → §6.6.2 최소 기간(6mo+)의 정량 근거.
- 연도 복원 로직(softcon DOM 날짜 무연도)은 무작위 10채널 화면 대조 스팟체크 + 월 경계(12→1월) 단위테스트로 검증 후 사용.
- **분류 임계 민감도:** 상승/정체/하락의 ±20% 임계는 규약이지 자연 상수가 아니다. 리포트에는 ±15%/±25%로 재분류한 민감도 결과를 병기한다.

#### 6.6.6 체급 교훈 재해석 *(v4 → v4.1)*

v4 §6.6.3은 "체급 25점을 제거해도 top 5 비율 중앙값 1.40x 유지"를 체급의 약함으로 해석했다. v4.1은 이를 다르게 읽는다: **가중 점수 한 축을 빼도 순위가 유지/전복된다는 것은 가중치 배분이 자의적이라는 증거**다. 그래서 체급 가중을 낮추는 게 아니라 **가중 스코어 자체를 폐기**했다. 체급은 이제 Track A의 완만한 레벨 밴드(0.7~1.5×L)로만 들어간다.

#### 6.6.7 데이터 전제와 프로파일 연결

- **P0:** 궤적매칭 미적용 (스냅샷 1장). 성장 전망 신호(§6.3.2) + 이정표 분포 서술만.
- **P1:** Track C(분포) + Track A(예측 밴드)까지.
- **P2:** 3트랙 전체 + Track B 행동 차이.
- 세 트랙 모두 **시계열 길이에 n이 비례**한다. 소프트콘 히스토리가 짧으면 트랙별 n 부족을 리포트에 명시하고, 결론을 흐리지 않는다. 근본 해결은 주간 스냅샷 축적(수집 로드맵 Phase C) — 시계열이 길어질수록 t0 탐색 가능 채널이 늘어난다.

**리포트 명시 한계** *(스펙 §9 승계)*:
- 관측 가능한 것은 공개 지표뿐 — 콘텐츠 질·커뮤니티 이벤트는 미관측 교란변수다.
- t0 정렬은 "레벨"만 맞추고 "시대"는 못 맞춘다 (2025년의 L명과 2026년의 L명은 경쟁 환경이 다름). α 조정으로 부분 완화에 그친다.

#### 6.6.8 산출물 *(2026-07-09 §6.6.10 정합)*

## 7. 콘텐츠 채널 효과 분석

### 7.0 외부 채널 상태 분류 *(v4 신설)*

분석 진입 전, 외부 채널의 현재 상태를 먼저 분류한다.

| 상태 | 기준 | 분석 경로 |
|---|---|---|
| **활성(active)** | 최근 3개월 내 콘텐츠 게시 있음 | §7.1~7.6 일반 분석 |
| **비활성(dormant)** | 3~12개월 게시 없음. 채널·계정 존재. | §7.7 비활성 타당성 패턴 |
| **부재(absent)** | 12개월+ 게시 없음 또는 채널 삭제 | §7.7 (간소화 적용) |

하나의 대상 채널이 복수 외부 채널을 운영할 때, 채널별로 상태가 다를 수 있다. 각각 분류한다.

### 7.1 외부 콘텐츠 유입 측정

대상 채널이 운영하는 외부 채널(유튜브 숏폼·인스타·트위터 등)이 *주 채널 성장에 기여*하는지 측정.

**핵심 질문:** 그 콘텐츠의 도달(조회수)이 주 채널 팔로워·시청자 증가로 *전환*되는가?

**방법:**
1. 외부 콘텐츠 게시일 식별
2. 게시일 전후 N일의 주 채널 팔로워 증가율 비교
3. 평소 증가율과의 차이 = 전환 효과

### 7.2 정체성 정합도 평가

전환되더라도, 유입된 시청자가 *정체성과 결이 맞는지* 확인. 결이 안 맞으면 잔류 안 함.

콘텐츠 유형별 분류:
- **결 맞음:** 주 카테고리와 일치하는 콘텐츠
- **결 일부:** 정체성을 변형하여 적용한 트렌드
- **결 안 맞음:** 순수 트렌드 추종 (도달은 크나 정체성과 무관)

### 7.3 권장 방향

- 결 맞음 콘텐츠 → **메인 레버**
- 결 일부 → 보조, 단 정체성 결합 필수
- 결 안 맞음 → 비주력 (도달용 환기 정도)

### 7.4 콘텐츠 세그먼트 샘플링 *(v2 신설)*

방송 전체를 하나의 콘텐츠로 보지 않는다. 실제 매력과 전환 후보는 방송 안의 특정 구간에서 나온다.

권장 컬럼:

```csv
vod_id,stream_date,vod_url,segment_id,segment_start,segment_end,segment_duration_min,content_mode,game_title,topic,identity_marker,entry_hook,residue_hook,chat_spike,viewer_reaction_type,clip_candidate,shorts_candidate,notes
```

| 구분 | 질문 |
|---|---|
| `content_mode` | 게임, 저챗, 리액션, 토론, RP, 기타 중 무엇인가 |
| `identity_marker` | §1 정체성 표지가 실제로 보이는가 |
| `entry_hook` | 처음 클릭할 이유가 있는가 |
| `residue_hook` | 남아 있을 이유가 있는가 |
| `shorts_candidate` | 외부 채널로 잘라낼 수 있는가 |

### 7.5 외부 채널 전환 퍼널 *(v2 신설)*

조회수와 본방 전환을 분리한다. 외부 콘텐츠는 많이 봤지만 주 채널 팔로워·시청자로 이어지지 않을 수 있다.

권장 컬럼:

```csv
platform,content_id,content_url,posted_at,content_type,content_topic,duration_sec,title,identity_fit,views,likes,comments,shares,click_to_chzzk_link_present,cta_present,follower_delta_1d,follower_delta_3d,follower_delta_7d,stream_peak_delta_next_stream,avg_viewer_delta_next_stream,conversion_assessment,notes
```

분석 원칙:

- 도달 지표: views, likes, comments, shares
- 전환 지표: follower_delta, next_stream_peak_delta, next_stream_avg_delta
- 정합 지표: identity_fit, CTA 존재, 본방 유입 경로 존재

### 7.6 시청자 수용 어휘 샘플 *(v2 신설)*

시청자가 무엇 때문에 남는지는 숫자만으로 안 보인다. 공개 반응에서 **반응 유형과 수용 어휘**를 익명화해 기록한다.

권장 컬럼:

```csv
sample_id,source_type,source_url,stream_date,segment_id,sampled_at,public_text_excerpt,anonymized,viewer_reaction_type,identity_term,positive_negative_neutral,target_claim,privacy_action,notes
```

원칙:

- 닉네임·ID 중심으로 저장하지 않는다.
- 공개 반응이라도 외부 산출물에는 요약·익명화한다.
- 반응은 개인 평가가 아니라 정체성 수용의 증거로만 쓴다.

### ⚠️ 함정

- **조회수만 보고 효과 판정.** 도달 ≠ 전환. 조회수 5만이어도 주 채널 유입 없으면 효과 약.
- **외부 채널 자체 자산화 무시.** 주 채널 전환은 안 돼도 *외부 채널 자체*(예: 유튜브 구독)는 자산일 수 있음. 별도 분석.

### 7.7 비활성 외부 채널 타당성 패턴 *(v4 신설)*

§7.0에서 dormant 또는 absent로 분류된 채널에 적용한다. "외부 채널이 죽어 있으니 분석 불필요"가 아니라, *재활성화할 가치가 있는지*를 판정한다.

#### 7.7.1 상위밴드 보유율 확인

§6.2의 상위밴드 데이터에서, 대상 채널과 같은 카테고리의 상위 채널 중 해당 외부 플랫폼을 보유한 비율을 확인한다.

- 80% 이상 보유 → 시장 표준. 보유하지 않으면 경쟁 열위 신호.
- 50% 미만 보유 → 카테고리 특성상 해당 플랫폼이 중요하지 않을 수 있음.

#### 7.7.2 외부 채널 ↔ 주 채널 상관

외부 채널이 활성이었던 기간의 데이터로, 외부 콘텐츠 게시일과 주 채널 시청자 변동의 상관을 계산한다.

- r ≈ 0 → 외부 채널이 주 채널에 기여하지 않았음. 재활성화 우선순위 낮음.
- r > 0.3 → 유의미한 기여. 재활성화 검토.
- 데이터 부족 (게시물 10건 미만) → 판정 불가로 명시.

#### 7.7.3 콘텐츠 유형별 유입 잔존율

외부 채널의 콘텐츠 유형별로 주 채널 유입 후 잔존율을 비교한다. *(v4.1 용어 정정: 여기서 "유입 잔존율"은 외부→본방 유입자가 남는 비율이며, §5.2.1의 잔류율(방송 1회 내 avg/peak)과는 다른 지표다.)*

*실전 사례 (구비바):* 유튜브 콘텐츠 유형별 유입 잔존율 — 하이라이트(shorts) > 편집 클립 > full_vod. full_vod가 가장 낮음 → full_vod 중심 재활성화는 비효율적.

#### 7.7.4 권장 방향

위 3단계 결과를 종합해 4가지 중 하나로 판정한다:

| 판정 | 조건 | 행동 |
|---|---|---|
| **재활성화 권장** | 상위밴드 보유율 높음 + 과거 상관 유의 | 콘텐츠 전략 수립 후 재개 |
| **형태 전환 후 재활성화** | 상위밴드 보유율 높음 + 특정 유형만 효과 | 효과 있는 유형 중심으로 재설계 |
| **현상 유지** | 상위밴드 보유율 낮음 또는 상관 ≈ 0 | 현재 비활성 상태 유지. 자원을 주 채널에 집중 |
| **판정 불가** | 데이터 부족 | 소규모 테스트(2주~1개월) 후 재판정 |

### 산출물

- 콘텐츠 유형별 전환 효과표
- 콘텐츠 세그먼트 샘플 표
- 외부 채널 전환 퍼널 표
- 시청자 수용 어휘 샘플 표
- 권장 콘텐츠 방향
- 비활성 채널 타당성 판정표 (해당 시)

## 8. 외부 교차검증 (XGPS)

### 8.1 검증 대상 선정

*가장 뒤집힐 가능성이 있는 결론* 또는 *가장 중요한 결론*을 외부에 던진다.

권장 검증 대상 (3개 정도):
- 가장 큰 정정이 있었던 결론
- 핵심 보정 가정 (예: 노방종 보정)
- 핵심 전략 결론

### 8.2 발화 설계 — 우리 결론·보정 숨기기

XGPS 발화의 핵심 원칙: **외부 모델이 우리 결론을 추정하지 못하게.**

```
[금지] "이 채널이 성장 중이라는 우리 분석이 맞나?"
[금지] "이 데이터에 노방종 착시가 있는데 확인해줘"
[권장] "첨부한 데이터에서 이 채널이 성장 중인지 정체인지 판정해줘"
[권장] "첨부 데이터의 평균시청자 지표를 주 지표로 써도 되는지 평가해줘"
```

원시 데이터만 첨부, 우리 보정·해석은 *전부 제거.*

### 8.3 수렴·발산 처리

| 결과 | 해석 |
|---|---|
| **수렴** (외부도 같은 결론) | 신뢰도 상승, 단 *상식 수렴*이면 약한 검증 |
| **발산** (외부가 다른 결론) | **XGPS의 진짜 수확.** 우리 맹점 가능성. 데이터로 다시 확인. |
| **수렴이되 정밀화** | 외부가 더 날카로운 표현 제공 — 받기 |

**가장 흔한 실수:** 발산을 *우리 결론 지키는 쪽으로 재해석.* 무마하지 말고 *데이터로 가르거나 미해소로 열어둘 것.*

### 8.4 같은 종(LLM) 한계 명시

- 외부 모델도 LLM이면 *공유 편향* 존재 가능
- 통계 상식 수준의 수렴은 "독립 검증"이 아니라 *상식 재확인*
- 진짜 가치는 *발산*과 *정밀화*

### 8.5 검증 입력 패키지 *(v2 신설)*

XGPS에는 결론이 아니라 **검증 가능한 입력 패키지**를 준다. 입력 패키지는 다음을 포함한다.

| 포함 | 제외 |
|---|---|
| 원시 일별 통계 | 우리 결론 문장 |
| 코호트 최종 CSV | 보정 해석 문장 |
| 코호트 방법론 요약 | 클라이언트 민감정보 |
| 콘텐츠 세그먼트 샘플 일부 | 개인 식별 가능한 시청자 반응 |
| 미해소 open 목록 | “이 결론 맞나?” 식 유도 질문 |

검증 결과는 `xgps_result.json` 또는 `xgps_report.md`로 남기고, 발산은 project.json open에 연결한다.

### ⚠️ 함정

- **발산을 자기방어로 재해석.** 발산은 *우리에게 불리한 신호*일수록 무마 욕구가 커진다 — 의식할 것 (부록 B 참조).
- **수렴을 "검증 완료"로 단정.** 수렴은 신뢰도 상승이지 검증 완료 아님.

### 8.6 진단 규칙 백테스트 *(v4.1 신설 — 실행 게이트: Phase C 시계열 축적 후)*

XGPS(LLM 교차검증)는 같은 종 한계가 있다(§8.4). 진짜 검증은 **진단 규칙이 예측력을 갖는지**를 코호트의 실제 이후 성과로 확인하는 것이다.

#### 8.6.1 원리

과거 시점 t의 지표만으로 진단 규칙을 적용하고, t+h(3·6개월)의 실제 성과와 대조한다. 예:

| 검증 대상 규칙 | 백테스트 질문 |
|---|---|
| 리텐션 하한 경보 (§6.3.1) | t 시점 리텐션_프록시 하위 25% 채널이 t+6에 실제로 정체·하락했는가 |
| 성장 전망 신호 (§6.3.2) | 효율·관성 상/하위 조합의 P(초과 성장) 분리(90%/7%)가 신규 기간에도 유지되는가 |
| 팔로워 1,500 변곡점 | t 시점 1,500 통과 채널의 "평청 14+" 달성률이 실제로 급등하는가 (단면 아닌 종단) |
| 방송량-시청자 무상관 | t 시점 방송량 증가 채널이 t+h에 시청자 증가로 이어지지 않았는가 |
| 6축 병목 진단 | 1차 병목 지표가 낮은 채널이 실제로 성장 제약을 받았는가 |

#### 8.6.2 실행 조건과 절차

- **게이트:** 동일 코호트의 시계열 스냅샷 2개 시점 이상 (주간 스냅샷 축적 — 수집 로드맵 Phase C). 단면 데이터로는 백테스트 불가.
- 절차: ①t 시점 스냅샷으로 규칙 적용 ②t+h 실측과 대조 ③규칙별 정밀도/재현율 기록 ④예측력 없는 규칙은 강등(관찰 등급) 또는 폐기.
- 결과는 규칙별로 `claim_level`(§14.7)을 갱신하는 근거가 된다 — 백테스트 통과 규칙만 L3(pattern_correlation) 이상을 주장할 수 있다.

#### 8.6.3 함정

- **미래 정보 누출(lookahead).** t 시점 판정에 t 이후 정보(현재 세그먼트 라벨 등)가 섞이면 백테스트가 무효다. 스냅샷 시점 필드만 사용.
- **생존 편향.** t+h에 관측되지 않는 채널(은퇴·휴면)을 분모에서 조용히 빼면 성과가 부풀려진다. 이탈도 결과의 하나로 집계.

#### 산출물

- 규칙별 백테스트 결과표 (정밀도·재현율·n·기간)
- claim_level 갱신 기록

#### 8.6.4 1차 실행 결과 (2026-07-08) *(v4.1 실측)*

게이트 해소: 뷰어십 통계 사이트 채널 페이지에 주간 시계열 53주(2025-07~2026-07)가 내장되어 있어 Phase C 축적 없이 즉시 실행함. 데이터: 버튜버 census 층화 표본 999채널(large 전수 226 + growth 550 + rookie 223, 이탈 포함), 엔진 `tools/backtest/`, 전방 창 12주, 시장조정 α(세그먼트 중앙값 대비 상대 성장률).

| 규칙 | 판정 | 근거 | claim_level 조치 |
|---|---|---|---|
| 방송량-시청자 무상관 | **지지** | ρ=0.041 (n=18,376 채널-주) — 방송량 percentile과 전방 12주 상대 성장 사실상 무상관 | L3 유지 가능 |
| 성장 전망 신호 (§6.3.2, 효율×관성) | **지지** | 청신호 55.3% vs 적신호 5.7% vs 기저 28.6% (이탈=정체 포함, n=25,000 채널-주; 생존자만 lift +0.50/+0.44) — 전 기간에서 분리 유지 | **L3 등재** (분기 재백테스트 조건) |
| 리텐션 하한 경보 | 기각 | risk_diff −0.23 (이탈=정체 포함) / −0.08 (생존자만). 하위 25% 밴드 4주 연속이 이후 상대 성장 정체를 예측하지 못함 | **L2 강등** — 내부 가설로 유지, 클라이언트 단정 금지 |

| 6축 병목 판정 | 기각 | severity 순위상관 +0.04 (예측 방향 반대·사실상 0), lift 음수 | **L2 강등** — 병목 판정은 단면 진단 도구로만, 예측 주장 금지 |

**전수 재검증 (2026-07-09, 7,472채널)**: 위 5규칙 판정 **전부 동일** (표본 999→7,472, 약 7.5배). 성장 전망 신호 청 55.8%/적 7.4%/기저 28.8% (n_green 23,027), airtime 지지 유지 — 판정은 표본 우연이 아님 확인. 원 결과 `runs/census_full_20260708/backtest_results.json`. 궤적매칭 중간 체급 미확정은 전수로 해소 (§6.6.10).

**해석 주의 (자기방어 함정 경계와 정직성 사이):**
- 기각은 "이 조작화(주간 프록시·풀링 단면·12주 창)에서 예측력 없음"이지 규칙 개념 자체의 반증은 아니다. 단, **클라이언트 산출물에서 L3급 단정을 계속 쓰는 것은 이제 근거 없음이 확인된 상태**다.
- 리텐션 기각에는 선택 효과 주의: 신호 자체가 "4주 연속 방송"을 요구해 생존 채널로 조건화된다. 본인 일별 데이터 기반 리텐션_직접(P2)은 이 백테스트의 대상이 아니다.

## 10. 실행 설계 *(v1 신설)*

> v0의 가장 큰 빈 곳. 분석 끝나면 *what만 있고 how 없음*. **이 영역이 컨설팅의 *진짜 가치 영역*.**

### 10.1 What → How 변환 원칙

분석 결과(§5·§6·§7·§8 산출)는 *전략 수준*. 클라이언트는 *행동 수준*이 필요.

| 수준 | 형식 예 |
|---|---|
| 전략 (§9 산출) | "X의 'Y'화" — 추상 |
| 액션 (§10) | "방송 시작 5분에 [행동] 3회·중간 [행동] 멘트 3회" — 동사+시간+횟수+대상 |
| 트래킹 가능 단위 (§11) | "방송 1회당 액션 횟수 / 1주일 누적 / 한 달 지표 변화" |

→ 같은 전략도 *액션·트래킹 단위*까지 내려야 클라이언트가 *실행 가능*.

### 10.2 액션 분해 4단계

1. **추상 → 구체 행동**
   - 전략 1개 → 행동 3~5개로 분해
   - 행동은 *동사 + 시간·횟수·대상* 형태

2. **시간 단위 매핑**
   - 각 행동을 *방송 한 회·일주일·한 달* 중 어느 단위에 적용할지 명시

3. **진입장벽 가장 낮은 1개 식별**
   - 클라이언트가 *내일 방송에서 시작할 수 있는* 1개를 명시
   - 진입장벽 ≠ 효과 크기. *지속 가능한 시작점*이 진입장벽 낮은 행동.

4. **본인 자원·기질 점검**
   - 클라이언트 시간 자원 (§I 답변 활용)
   - 클라이언트 기질 (예: 갈등 회피·완벽주의 회피·자가 회복 메커니즘)
   - 자원·기질에 맞지 않는 액션은 *외부 의존*으로 전환 (편집자 구인·소속사 위임 등)

### 10.3 실행 매뉴얼 구조

산출물 형식 (MD):

```
## 액션 1: [추상 전략 이름]

### 다음 방송에서 시작할 1가지
[가장 진입장벽 낮은 1개 행동 — 1문장]

### 매 방송 행동 (5~10분 추가)
- [구체 행동 1]
- [구체 행동 2]

### 매 주 행동 (1~2시간)
- ...

### 매 월 행동 (집중 작업)
- ...

### 트래킹 단위
- 방송 1회: [지표]
- 1주: [지표]
- 1달: [지표]

### 효과 판정 시점
- [N일 후 무엇을 보고 판단할지]

### 실패 시 조정 기준
- [지표 X 이하 → 행동 Y로 조정]

### 본인 자원·기질 고려
- 시간 부담: [추정]
- 자원 의존: [편집자·도구 등 / 자체 가능]
- 기질 호환: [본인 자기 검열·완벽주의 등 점검]
```

### 10.4 액션 우선순위

분석된 응대 우선순위(§9에서 박힘)에 따라 액션 우선순위 결정.

| 우선순위 | 액션 형태 |
|---|---|
| 1순위 (응대 핵심) | 자기 의심·자기 검열 등 *정체성 영역* 직접 해소 액션 — 데이터 발견 정량화·시청자 의견 수집 등 |
| 2순위 (콘텐츠) | 콘텐츠 확장·트렌드 대응 |
| 3순위 (외부 채널) | 유튜브·SNS 운영 — 본인 자원·진입장벽 점검 후 |
| 4순위 (구조 변화) | 소속사 가입·편집자 외주 등 — 본인 의사결정 시점에 따라 |

### 10.5 실행 장벽 분류 *(v2 신설)*

실행 실패는 곧바로 의지 부족으로 보지 않는다. 어떤 장벽에서 멈췄는지 분류한다.

| 장벽 | 의미 | 전환 방향 |
|---|---|---|
| 시간 | 할 시간이 없음 | 액션 축소·빈도 낮춤 |
| 기술 | 편집·도구 사용이 막힘 | 템플릿·외부 도움 |
| 완벽주의 | 완성 기준이 높아 시작/완료 안 됨 | 70% 기준·샘플 업로드 |
| 자기 검열 | “내가 해도 되나”에서 막힘 | 시청자 설문·외부 검증 |
| 외부 의존 | 혼자 할 수 없는 구조 | 편집자·소속사·도구 연결 |
| 불안/과부하 | 전달 후 걱정 폭주 | 즉답 금지·회복 시간 확보 |
| 결 불일치 | 액션이 정체성과 안 맞음 | 액션 폐기·대체 |

권장 컬럼:

```csv
action_id,action_name,action_type,planned_date,stream_date,trigger_condition,expected_effort_min,actual_effort_min,completed_status,completed_count,barrier_type,barrier_detail,self_burden_score,confidence_before,confidence_after,needs_external_help,next_adjustment,metric_window,peak_delta,chat_delta,follower_delta,notes
```

### 10.6 액션은 처방이 아니라 실험 *(v2 신설)*

실행 매뉴얼의 각 액션은 “하라”가 아니라 “검증하라”에 가깝다. 액션마다 다음 5개를 붙인다.

| 항목 | 질문 |
|---|---|
| 가설 | 이 액션이 무엇을 바꿀 것인가 |
| 최소 행동 | 가장 작은 실행 단위는 무엇인가 |
| 성공 신호 | 어떤 행동/결과가 나오면 성공인가 |
| 실패 신호 | 어디서 막히면 실패인가 |
| 조정 | 실패 시 낮출 것인가, 외부화할 것인가, 폐기할 것인가 |

### ⚠️ 함정

- **추상 전략을 실행 매뉴얼로 위장.** 전략은 액션이 아님. 클라이언트가 *내일 무엇을* 하는지 안 보이면 실행 매뉴얼 아님.
- **진입장벽 무시한 액션 권고.** 본인 기질·자원에 안 맞는 액션은 *시도 안 됨* → 컨설팅 효과 0. 진입장벽 낮은 1개부터.
- **외부 의존 액션을 *본인 행동*으로 권고.** 본인이 *못 할 영역*은 외부 의존으로 명시 + *대안 액션 동시 제시*.

## 11. 실행 지원 *(v1 신설)*

> 클라이언트가 액션 실행 *중*에 우리가 무엇을 하는가. 분석가의 역할이 *진단*에서 *코칭*으로 이동.

### 11.1 트래킹 시트 설계

§10에서 정의한 *트래킹 단위*를 *실제 측정 가능한 시트*로 변환.

**구조:**

| 일자 | 방송회차 | 액션1 수행 (○/△/×) | 액션1 횟수 | 액션2 ... | 지표 X | 지표 Y | 본인 메모 |
|---|---|---|---|---|---|---|---|

- *액션 수행 자체* 트래킹 + *지표 변화* 트래킹
- 본인이 *직접 기록*하거나 *자동 수집* 가능한 형태로
- 부담 최소 — 한 방송당 입력 3~5분 이내

### 11.2 효과 판정 주기

| 주기 | 점검 내용 |
|---|---|
| 매 방송 | 액션 수행 자체 (○/△/×) |
| 매 주 | 액션 누적 + 단기 지표 (채팅·peak·체류) |
| 매 월 | 누적 지표 + 추세 (팔로워·구독·반복 시청) |
| 분기 | 응대 핵심 영역 (자기 의심·자기 검열) 변화 — 인터뷰 1회 |

### 11.3 조정 신호 처리

트래킹에서 발견되는 신호 3종 처리:

| 신호 | 처리 |
|---|---|
| **액션 수행 미이행** | 진입장벽 분석 — 시간? 기질? 자기 검열? 외부 의존 액션으로 전환 검토 |
| **수행했으나 지표 변화 없음** | 액션 자체 효과 부족 — 액션 조정 또는 응대 핵심 영역 재점검 |
| **지표 변화 있으나 부정적** | 액션 중단 + 원인 분석 + 대안 액션 설계 |

### 11.4 클라이언트 소통 주기

| 빈도 | 형식 |
|---|---|
| 매 방송 | 트래킹 시트 본인 기록 (우리 개입 없음) |
| 매 주 | 짧은 메시지 (트래킹 시트 점검·격려) |
| 매 월 | 1회 응대 (지표 리뷰 + 다음 달 조정) |
| 분기 | 깊이 인터뷰 (응대 핵심 영역 변화 점검) |

### 11.5 본인 자기 평가 기준 재조정

§3 측정 보정의 자기 평가 함의가 *실행 단계에서 다시 작동*. 본인이 *지표 의존 자기 평가*를 하는 경우, *액션 효과를 그 지표로만* 보면 *측정 착시*에 빠짐.

→ 트래킹 시트에 *행동 지표*(액션 수행 자체)와 *결과 지표*(채팅·peak)를 *분리* 명시.

### 11.6 행동 지표와 결과 지표 분리 *(v2 신설)*

자기 검열형·자기 의심형 클라이언트에게 결과 지표만 보여주면 단기 미달이 자기 의심 강화로 작동할 수 있다.

| 구분 | 예시 | 해석 |
|---|---|---|
| 행동 지표 | 액션 수행 여부, 타임스탬프 수, 업로드 수 | 본인이 통제 가능 |
| 과정 지표 | 부담 점수, 소요 시간, 장벽 유형 | 실행 가능성 평가 |
| 결과 지표 | peak, 평균 시청자, 채팅, 팔로워 | 외부 반응. 단기 변동 큼 |

트래킹 시트는 행동 지표를 앞에 두고 결과 지표를 뒤에 둔다. 결과가 안 나와도 행동 수행이 성공이면 “실패”가 아니라 “효과 미검증”으로 둔다.

### 11.7 실행 중 부재 갱신 *(v2 신설)*

실행 단계에서 새 부재가 발견된다. 예를 들어 “쇼츠가 없음”, “시청자 설문이 없음”, “편집자 루트가 없음”은 단순 빈칸이 아니라 다음 액션을 정하는 데이터다.

처리 방식:

- 새 부재 발견 → `absence_inventory.csv`에 추가
- 실행 미이행 → `execution_tracking.csv`에 barrier_type 기록
- 수집 실패와 실제 부재를 분리
- 다음 월간 점검에서 부재가 해소됐는지 재확인

### ⚠️ 함정

- **트래킹 시트가 *클라이언트 부담*.** 한 방송 3~5분 이상 걸리면 *지속 안 됨*. 부담 최소가 첫 원칙.
- **지표만 보고 본인 자기 평가 강화 (v1 신규).** 본인이 *자기 검열형*이면 단기 지표 미달이 *자기 의심 강화*로 작동. 트래킹 시트에 *맥락·정정 안내* 동반.
- **분기 깊이 인터뷰 빠뜨림.** 응대 핵심 영역(자기 의심·자기 검열) 변화는 *지표로 안 보임*. 분기 인터뷰 필수.

### 산출물

- 트래킹 시트 (CSV 또는 Google 시트 링크)
- 실행 데이터셋 (`execution_tracking.csv`)
- 효과 판정 주기 정의표
- 조정 신호 처리 매뉴얼
- 업데이트된 부재 인벤토리

## 12. 후속 응대 *(v1 신설)*

> 실행 단계 *이후* 장기 관계. 단기 컨설팅 끝나도 *케이스가 끝나지 않은* 영역.

### 12.1 응대 형태 3종

| 형태 | 시기 | 비용 |
|---|---|---|
| **선행지표 검증** | 산출물 전달 후 3~6개월 | 1~2 세션 |
| **재진단 (분기·반기)** | 분기·반기 | 부분 분석 재실행 |
| **장기 케이스 모니터링** | 1년+ | 가벼운 점검 |

### 12.2 선행지표 검증

§10 실행 매뉴얼에서 정의한 *효과 판정 시점*에 도달했을 때, 액션 효과를 *데이터로* 확인.

### 12.3 재진단 트리거

다음 신호 발견 시 *부분 재진단* 실행:

- 응대 핵심 영역(자기 의심 등)에 *큰 변화*
- 외부 환경 변화 (플랫폼·시장)
- 본인 사업 단계 변화 (전업화·축소·전환)
- 단기 지표의 *예상 외 변화* (급성장 또는 급락)

### 12.4 장기 케이스 모니터링

가벼운 형태:
- 분기 1회 짧은 점검 (15~30분)
- 본인 자발 질문 시 응답 (개방형)
- 새 발견·새 영역 발생 시 *재 패키징*

### 12.5 케이스 종료 결정

후속 응대도 영원하지 않음. 종료 결정 기준:

- 본인이 *컨설팅 졸업* 명시
- 본인 영속 의향과 *우리 응대 범위* 어긋남
- *데이터 부재로* 후속 분석 불가
- 본인이 *다른 체계*로 이동 (소속사 등)

→ 종료 시 *익명화 사례 활용 동의* 재확인.

### ⚠️ 함정

- **선행지표 검증 잊음.** 산출물 전달 시 *검증 시점 명시*하고 *프로젝트 open 항목으로 박기*.
- **재진단 트리거 인지 부재.** 본인 변화를 *외부 발견 없이* 알기 어려움. 트래킹 시트의 *분기 인터뷰* 또는 본인 자발 보고에 의존.

### 산출물

- 선행지표 검증 보고
- 재진단 결과 (트리거 발생 시)
- 케이스 종료 보고서 (종료 시)

## 13. 케이스 클로즈 기준 *(v0 §10 이동·갱신)*

### 13.1 분석 클로즈

다음 모두 충족 시 *분석 단계 완료* 선언.

- [ ] 정체성 확정 (§1 산출물)
- [ ] 코호트 구축 + 강건성 검증 (§4 산출물)
- [ ] 6단계 진단 완료 (§5 산출물)
- [ ] 트레이드오프 정량화 (§6 산출물)
- [ ] 콘텐츠 채널 효과 분석 (§7 산출물)
- [ ] XGPS 핵심 결론 검증 (§8 산출물)
- [ ] 클라이언트 리포트 1종 산출 (§9)
- [ ] 미해소 항목 open으로 박음

**용어 정정 (v1):** v0의 "하프 클로즈"를 **"분석 클로즈"**로 명명. *분석 완료*가 *케이스의 절반*이 아니라 *분석 단계의 종결*임을 명확히. 컨설팅 본질은 *§10 이후 실행 단계*.

### 13.2 실행 클로즈 *(v1 신설)*

분석 클로즈 + 다음 충족 시.

- [ ] 실행 매뉴얼 산출 (§10 산출물)
- [ ] 트래킹 시트 운영 시작 (§11 산출물)
- [ ] 진입장벽 가장 낮은 1개 행동 시작 확인 (본인 자발 또는 데이터)
- [ ] 단기 효과 1회 점검 (방송 1~3회 후)

### 13.3 완전 클로즈

분석 클로즈 + 실행 클로즈 + 다음.

- [ ] 선행지표 검증 1회 (산출물 전달 후 3~6개월)
- [ ] 본인 자기 평가 변화 (분기 인터뷰)
- [ ] 미해소 발산이 해결 또는 *영구 미해소 결정*

**일반적으로 완전 클로즈는 한 세션에 안 됨.** 분석 클로즈가 *분석 프로젝트*의 기본 종결, 실행 클로즈가 *실행 프로젝트*의 기본 종결, 완전 클로즈는 *장기 관계*의 종결.

### 13.4 v2 클로즈 추가 조건

v2부터 분석·실행 클로즈에는 다음이 추가된다.

| 클로즈 | 추가 조건 |
|---|---|
| 분석 클로즈 | 수집 근거 패키지, 부재 인벤토리, 카테고리 신뢰도, peak 다중 기준표 보존 |
| 산출물 클로즈 | 통합 진단 반응 로그 또는 반응 대기 open 기록 |
| 실행 클로즈 | 실행 장벽 분류표와 행동/결과 지표 분리 트래킹 시작 |
| 완전 클로즈 | 선행지표 검증 + 부재 재확인 + 미해소 발산 처리 |

**원칙:** 결론만 닫지 말고, 결론의 근거·부재·반응·실행 가능성까지 같이 닫는다.

### 13.5 프로파일별 클로즈 *(v4.1 신설)*

§13.1~13.3의 클로즈 기준(§7·§8 필수, 실행 단계 완료 포함)은 **P2(Deep-Dive) 표준**이다. §0.9 프로파일 도입으로 클로즈도 프로파일별로 스코프된다.

| 프로파일 | 클로즈 기준 |
|---|---|
| P0 | 케이스 아님 — 클로즈 없음 (project.json 미생성) |
| P1 | **P1 축약 클로즈**: §13.1에서 §7은 상태분류(§7.0)로, §8은 핵심결론 1개로 충족 처리. §10~12는 P1 범위 외 (실행은 P2 실행형 이상). §0.7.2의 "실행 완료 포함" 원칙은 P2에 적용된다. |
| P2 실행형 (PREMIUM) | P1 클로즈 조건 + 실행 우선순위 설계 전달 + **4주 체크인 완료 시점에 클로즈** (모니터링 캡이 클로즈 트리거 — 연장은 별도 계약) |
| P2 | §13.1~13.3 전체 (분석·실행·완전 클로즈 3단) |

즉 P1은 §13.1 전체 체크박스를 강제받지 않고, 상품 티어에 맞춘 축약 클로즈로 종결한다. 생략 항목은 산출물 범위 고지(§0.9.3)에 명시한다.

## 14. Case-to-Portfolio Bridge *(v3 신설)*

### 14.1 목적

Case-to-Portfolio Bridge는 개별 스트리머 Deep-Dive 결과를 MCN이 비교·선별·육성·스카우팅할 수 있는 포트폴리오 row로 변환하는 어댑터다.

```text
개별 케이스 산출물
  ↓
CaseResult JSON
  ↓
Bridge Adapter
  ↓
PortfolioRow JSON + DecisionCard
  ↓
MCN 포트폴리오 집계 / 육성 / 선별 / 스카우팅 / 벤치마킹
```

Bridge는 새 판단자가 아니다. Bridge는 CaseResult와 evidence package에 이미 존재하는 판단을 정규화한다. CaseResult에 없는 결론을 만들어 PortfolioRow에 넣지 않는다.

### 14.2 입력

Bridge의 최소 입력은 다음과 같다.

| 입력 | 설명 |
|---|---|
| `project.json` | claim, open, action, absence, disclosure 레지스터 |
| `CaseResult.json` | 개별 케이스 진단 요약과 evidence refs |
| `cohort_final.csv` | §4 최종 코호트와 구비바/대상 위치 |
| `diagnosis_summary.md` | §5 6단계 진단 요약 |
| `execution_tracking.csv` | §10·§11 실행 반응성 데이터 |
| `absence_inventory.csv` | 실제 부재, 수집 실패, 미검증 구분 |
| `DisclosureLog.jsonl` | 공개·부분공개·비공개 태깅 이력 |

### 14.3 출력

| 출력 | 대상 | 설명 |
|---|---|---|
| `PortfolioRow.json` | MCN 내부 | 포트폴리오 표에 들어가는 한 줄 |
| `DecisionCard.md` | MCN 담당자/운영자 | 사람이 읽는 자원배분 카드 |
| `PublicDemoRow.json` | 프리프린트/공개 데모 | 익명화·합성 처리된 공개 가능 row |

### 14.4 Readiness Gate

Bridge는 변환 전에 readiness를 판정한다.

| 상태 | 의미 | 처리 |
|---|---|---|
| `not_ready` | 핵심 단계 미완료 | 변환 금지 |
| `pre_portfolio_only` | 방향성만 있음 | 점수 없이 blocking reason 기록 |
| `partial_ready` | 일부 필드 가능 | confidence 낮음으로 제한 출력 |
| `portfolio_ready` | 내부 포트폴리오 사용 가능 | PortfolioRow + DecisionCard 생성 |
| `public_demo_ready` | 공개 안전성 통과 | PublicDemoRow 생성 가능 |

### 14.5 채널진단 단계별 매핑

| 채널진단 단계 | PortfolioRow 필드 |
|---|---|
| §1 정체성 | `identity_clarity_score`, `identity_risk`, `content_fit` |
| §4 코호트 | `cohort_cell_id`, `cohort_confidence` |
| §5 진단 | `current_level_score`, `growth_velocity_score`, `primary_bottleneck`, `retention_alert_status`, `retention_metric_type`(direct/proxy) |
| §6 목표 | `intervention_fit`, `support_acceptance_score` |
| §7 콘텐츠 | `content_expansion_readiness`, `external_funnel_status` |
| §9 산출물 반응 | `messaging_risk`, `support_acceptance_score` |
| §10 실행 | `execution_readiness_score`, `intervention_candidates` |
| §11 트래킹 | `intervention_responsiveness_score`, `barrier_profile` |
| 부재 인벤토리 | `absence_flags`, `data_quality_score` |

### 14.6 점수와 신뢰도

v3는 점수를 0~100으로 둘 수 있지만, 초기 운영에서는 등급도 허용한다.

```text
unknown / low / medium / high
```

단, 모든 점수에는 다음을 붙인다.

```text
evidence_refs
claim_level
confidence
disclosure_tag
missing_reason
```

### 14.7 Claim Confidence Ladder

| 레벨 | 이름 | 의미 |
|---|---|---|
| L0 | observed | 관찰됨 |
| L1 | descriptive | 기술통계로 확인됨 |
| L2 | cohort_relative | 코호트 대비 확인됨 |
| L3 | pattern_correlation | 함께 움직이는 패턴 확인 |
| L4 | intervention_candidate | 개입 후보로 제안 가능 |
| L5 | intervention_validated | 실행 후 반응으로 검증됨 |

### 14.8 산출물

- `CaseResult_v3.json`
- `PortfolioRow_v3.json`
- `DecisionCard.md`
- `PublicDemoRow_v3.json`
- `BridgeReadinessReport.md`

## 15. 공개·부분공개·비공개 경계 운영 *(v3 신설)*

### 15.1 기본 원칙

```text
무엇을/왜 = 공개 가능
어떤 개념으로 = 부분 공개 가능
정확히 어떻게/얼마나/어떤 데이터로 = 비공개
```

v3의 공개경계는 `green/yellow/red` 3단계다. 기존의 공개/비공개 이분법은 방법론 보호에 부족하다. 실제 IP는 “개념은 공개할 수 있지만 값과 도출 데이터는 숨겨야 하는” yellow 영역에 집중된다.

### 15.2 Disclosure Boundary Matrix

| 영역 | 🟢 공개 | 🟡 부분 공개 | 🔴 비공개 |
|---|---|---|---|
| 프레임워크 | 3면 검증, 6단계 진단, 실행 트래킹 구조 | 코호트 매칭 방법론, 필터 단계 개념 | 정확 필터 임계, 검증 데이터, 케이스별 근거 코호트 |

## 부록 D. 본인 검증 절차 *(v4.1 작성)*

에디터(분석가)의 통합 해석·정체성 추출 가설을 본인 명시 확인 없이 확정하지 않기 위한 절차 (§1 함정, §9.5, A.2 연결).

1. **가설 표시:** 분석 중 생성된 해석은 project.json에 `status: hypothesis`로 기록한다. 이 상태로는 클라이언트 리포트 본문에 단정형으로 쓸 수 없다.
2. **확인 발화 설계:** 유도 질문 금지. "우리는 X라고 본다, 맞나?"가 아니라 개방형으로 — "본인은 어떻게 정의하나 / 이 상황을 뭐라고 부르겠나".
3. **반응 기록:** §9.6 반응 로그에 수용/부분 수용/거부/과부하로 기록. 부분 수용이면 수용된 부분만 `confirmed`로 승격.
4. **승격 조건:** 본인 발화로 직접 확인되거나, 본인이 리포트 전달 후 명시적으로 동의한 경우에만 `hypothesis → confirmed`.
5. **불확정 유지:** 확인 기회가 없으면(P1 등 접점 최소 상품) 산출물에 "분석가 해석" 표기를 유지한다.

- [ ] **본인·커뮤니티 고유 어휘** (시청자 호칭, 자기 명명 스타일, 룰렛 슬롯명 등 — 기능어로 치환: "땡구 칭찬하기"→"시청자 칭찬하기")
- [ ] 절대 수치 중 식별 가능 항목 (수익 절대액, 팔로워 절대값 → 비율·범주로)
- [ ] 시청자 개인 단위 데이터 (후원자 명단·개인별 액수 — 집계로도 남기지 않음)
- [ ] 방송 스케줄·등급 등 조합 식별자
- [ ] 소속·계약 관계 단서

### K.2 유지 가능 (익명성 훼손 없이 가치 보존)

- 비율·배수 (예: "+139%", "2.4배") — 단 실측/시뮬레이션 구분 표기 필수
- 방법의 무게 (예: "6개월 후원 원장 전수 역산") — 건수는 식별성 낮으면 유지
- 구조·설계 수치 (예: 룰렛 확률 분포, 분당 단가) — 역으로 채널 특정 불가한 내부값
- 코호트 백분위 (예: "상위 14%")

### K.3 검증 3문

1. **역추적:** 이 문서만 들고 검색해서 채널을 특정할 수 있는가 (고유 어휘 1개면 뚫린다)
2. **동의 범위:** 익명화 사례 활용 동의가 이 배포 채널(크몽 페이지/콜드메일 첨부/유튜브)까지 커버하는가 — 채널별 별도 확인
3. **정직성:** 제안치·시뮬레이션을 실현 성과처럼 읽히게 두지 않았는가 (면책 문구 위치까지 확인)

### K.4 산출물 표기 (하단 고정 문구 틀)

> ※ 의뢰인 동의하에 모든 식별 정보(채널명·수익 절대액·시청자 정보·커뮤니티 용어)를 제거하고, 구조와 방법만 남겨 재구성했습니다. [수치 성격 고지: 실측/시뮬레이션].
