# 구비바 §4 Charles 진단 요청 v2

**목적:** 구비바 §4 코호트 구축을 위해 실제 수집 가능한 공개 데이터 경로를 진단한다.  
**주 코호트:** 치지직 종합게임 스트리머  
**보조 코호트:** 치지직 버추얼 스트리머  
**주의:** Charles는 수집자가 아니라 진단자다. 실제 대량 수집은 Arthur가 한다.

---

## 1. 진단 대상

### A. 종합게임 모집단

확인할 것:

- 종합게임/종합게임에 준하는 카테고리 랭킹을 얻을 수 있는 공개 경로.
- 가능한 수집량: 최소 상위 500명, 권장 상위 2,000명.
- 확보 가능 컬럼:
  - channel_name
  - channel_url
  - channel_id
  - source_rank
  - total_stream_hours
  - peak_viewers
  - avg_viewers
  - viewership
  - max_chat_6m / avg_chat_6m 가능 여부
  - aggregation_window_start/end

### B. 버추얼 모집단

확인할 것:

- 버추얼 스트리머 모집단을 얻을 수 있는 공개 경로.
- 종합게임 성향 버추얼을 추가 식별할 수 있는지.
- `is_virtual`, `virtual_basis`를 만들 수 있는지.
- 가능한 수집량: 필터 후 50명 이상.

### C. 팔로워 매칭

확인할 것:

- channel_id 또는 channel_url 기준 follower_count를 매칭할 수 있는 경로.
- follower_rank, follower_collected_at 확보 가능 여부.
- 코호트 후보 전원 매칭 가능 여부.

---

## 2. 최소 컬럼 확보 가능성 판정

각 출처마다 다음 표를 작성한다.

```csv
source_name,source_url,cohort_type,public_access,login_required,checkpoint_or_429,aggregation_window,available_columns,missing_columns,raw_type,notes
```

최소 통과 컬럼:

```csv
channel_name,channel_url,total_stream_hours,peak_viewers,avg_viewers,viewership,follower_count,primary_category
```

팔로워가 같은 출처에 없으면 follower source를 별도로 찾는다.

---

## 3. 접근 마찰 기록

다음은 중단 결론이 아니라 `boundary_signal`로 기록한다.

```text
429
checkpoint
login_required
rate_limit
parse_failed
data_missing
aggregation_window_unknown
```

단, 다음이 필요하면 중단한다.

```text
비공개/회원전용 자료
타인 계정 세션/쿠키
개별 시청자 추적
맞춤형 checkpoint 통과 코드
반복 재시도/우회 루프
```

---

## 4. Charles 출력 형식

Charles는 다음 JSON을 출력한다.

```json
{
  "diagnostic_id": "gubiba_cohort_charles_YYYYMMDD",
  "status": "ready_for_arthur | partial | blocked",
  "source_candidates": [],
  "column_availability": [],
  "boundary_signals": [],
  "absence_inventory_updates": [],
  "recommended_execution_protocol": {}
}
```

---

## 5. Arthur에게 넘길 때 필요한 것

Charles 결과에는 최소한 다음이 있어야 한다.

- source_url
- request_url 또는 browser route
- cohort_type
- aggregation_window_start/end
- pagination 또는 cursor 구조
- request budget
- expected raw type: html/json/rsc
- available columns
- missing columns
- boundary_signal handling

---

## 6. 구비바 기준 peak band

Arthur가 필터링까지 하지는 않아도 되지만, 수집량 예산 산정에는 아래 기준을 참고한다.

| 기준 | band |
|---|---|
| recent median | 11.5~46 |
| all median | 10~40 |
| p95 | 18.85~75.4 |
| raw max | 74~296 |

raw max 기준은 스파이크 검증용이다. 본문 코호트는 recent median/all median 중심으로 구성한다.
